## 1. 背景

### 1.1 対象

勾配の長軸縮約（dw の行方向蓄積・bias 勾配の行方向縮約等）の Metal 実装形は
`AGENTS.md`・`.claude/rules/coding-rust.md` の既存契約（正規化統計・勾配の長軸縮約は
`f64` アキュムレータで統一する。イシュー #1102・ユーザー承認 2026-09-01）に従い
**Neumaier 改良版 Kahan 補償和 + 2 の冪 scale**（`bias_pow2_floor`。列内の要素の最大
絶対値以下の最大の 2 の冪で括り出す。除算・比は 2 の冪同士の演算のため、商が f32
正規化数の範囲内であれば exact（丸めが発生しない）であり、scale/ssq 方式〈正規化
統計の二乗和向け〉とは異なり誤差項を追加しない。範囲外（underflow）の場合の扱いは
「3.4 2 の冪 scale の underflow 誤差の吸収」を参照）として実装する。
MSL（Metal Shading Language）は `double` 型非対応のため、この実装形は f32 のみで
構成され、ホスト（CPU）`f64` 蓄積・CUDA `double` 蓄積と**厳密同値にはならない**
（2026-09-12 ユーザー承認済みの事実。イシュー #1566）。

実装は 1 出力列（bias の 1 要素）につき 1 thread が担当し、`m` 行（`n = m`。縮約対象
要素数）を完全逐次で Neumaier 補償和する構成（`crates/backend-metal` の Metal カーネル。
PR #1659）である。参照実装（ホスト側の真値相当）は `reduce_bias_grad_rows_host`
（CPU 側テストユーティリティ）・`eval::reduce_bias_grad_rows`（tape 評価経路。いずれも
index 順の `f64` 逐次加算）である。

### 1.2 当初案の問題点（P1・1 回目）

「1. 背景」冒頭 1. のとおり。`.claude/rules/security.md`「自己修復ループ固有のガード
レール」・`.claude/rules/coding-rust.md`「テスト・ベンチ」節が要求する「バックエンド間
数値一致テストの許容誤差を単独で緩和しない」の趣旨に照らして妥当な指摘であり、除外を
廃した 2 層契約（Tier A/B）へ改めた。

### 1.3 O 記法・参照値混同の問題点（P1・2 回目／P2）

本ドキュメント初版の Tier A は上界式に `O(n · ε32²) · Σ|x_i|` という 2 次誤差項を
含めていたが、係数が「無視できるとみなす」としか記述されておらず、具体的な数値として
計算できなかった（P1・2 回目）。また Tier A は「ホスト `f64` 逐次和を 1 回だけ `f32` へ
downcast した値 `y_f64`」、Tier B は「ホスト `f64` による厳密和（真値）`S_f64`」という
異なる 2 つの概念を、酷似した表記（`y_f64`／`S_f64`）で扱っており、実際にはどちらも
テストが比較する対象は無限精度の真値ではなく `reduce_bias_grad_rows_host` 等の参照
実装の出力である（P2）。本ドキュメントはこれらを是正し、二次項を含めて全て明示係数の
式とし、参照値を単一の記号 `S_ref`／`y_ref` として定義し直す。

### 1.4 未定義領域の問題点（P1・3・4 回目）

本ドキュメント第 2 版（Tier A/B の明示式化）は、有効範囲 `n < 2^24` を超える入力・
非有限値を含む入力についての扱いを定義しないまま残していた。範囲外の `n` に対する
判定が未定義のままだと、実装側が「範囲外だから何もチェックしない」という無言の
フォールバックを取りうる余地が残る（P1・3 回目）。また Tier A の上界式は実数の
有限値を前提としており、入力に NaN／±inf を含む場合や、`S_ref` の `f32` downcast
自体が overflow して ±inf になる場合を扱えない（P1・4 回目）。本ドキュメントは
これらを「2.4 入力上限と範囲外の明示拒否」「2.5 非有限値の扱い」として追加する。

## 2. 2 層契約の定義

### Tier A（全入力に常に適用・除外なし）

Metal 出力 `y_metal` と参照値 `y_ref`（定義は下記）の誤差は、次の上界を常に満たす:

```
|y_metal − y_ref| ≤ (4 + n · ε32) · ε32 · Σ|x_i|
```

- `ε32 = 2^-24`（f32 の丸め単位）
- `n` は縮約対象要素数（行数 `m`）
- `Σ|x_i|` は参照実装（`reduce_bias_grad_rows_host`／`eval::reduce_bias_grad_rows`）が
  index 順に `f64` で累積した絶対値和
- 係数 `4` の導出・二次項 `n · ε32` の位置づけは「3. C の確定」節を参照
- **有効範囲は `n · ε32 < 1`（すなわち `n < 2^24`）**。この範囲外では上界式自体が
  意味を失う（左辺が `Σ|x_i|` を超えうる）ため、Tier A はこの範囲内の入力にのみ適用
  する。実用範囲（`n ≤ 2^20`）では `n · ε32 ≤ 2^-4` であり 1 次項（係数 4）に対し
  無視できるほど小さいが、上界としては式に残す

`y_ref` の定義: `S_ref`（参照実装が index 順に `f64` で逐次加算した和）を 1 回だけ
`f32` へ downcast した値。`S_ref` 自体は無限精度の真値ではなく、あくまで参照実装の
出力である（真値との差は「3.3 `S_ref` と真値の差」を参照）。

Tier A はこの有効範囲内のどの入力（人工的な相殺を含む）にも常に成立することが要求
される。Tier A が成立しない場合は実装のバグであり、除外や緩和の対象にはしない。

### Tier B（REQ-2 統一複合判定）

REQ-2 統一複合判定（相対誤差 1e-3 未満 または 絶対誤差 1e-5 未満）を厳密ゼロ fail 判定
として適用するのは、**入力から事前に計算できる述語**が成立する列に限る:

```
(4 + n · ε32) · ε32 · Σ|x_i| ≤ max(1e-3 · |S_ref|, 1e-5)
```

- `S_ref` は上記のとおり参照実装が index 順に `f64` で逐次加算した和（真値ではない）
- 左辺は Tier A の誤差上界そのもの、右辺は REQ-2 の絶対誤差 ceiling（`|S_ref|` が十分
  大きい場合は相対誤差 ceiling `1e-3・|S_ref|` が支配）
- この述語は列の**条件数** `κ = Σ|x_i| / |S_ref|`（相殺が大きいほど κ が大きい）の
  上限と等価であり、`Σ|x_i|` と `S_ref` の両方を計算する時点（＝実行前）で判定できる

この述語が成立しない列（例: `[2^48, 2^24, 1, -2^48, -2^24]`。`S_ref = 1` に対し
`Σ|x_i| ≈ 2^49` と極端に大きく κ が非常に大きい）は、REQ-2 統一複合判定の対象から
**除外するのではなく**、Tier A のみで判定する（Tier A は有効範囲内の全入力で成立が
要求されるため、安全性は失われない）。

### 除外方式との違い

当初案（初版・P1 1 回目以前）の「保持範囲を超える相殺は対象外」は、実測後に個々の
入力を見て事後的に「対象外だった」と判定する余地を残していた。Tier A/B は逆に、
**実行前に入力（`Σ|x_i|` と `S_ref`）だけから Tier A・Tier B のどちらで判定すべきかを
一意に決定できる**。かつ Tier B 不成立の列も無契約になるわけではなく、常に Tier A
（より緩いが無条件の上界）で判定される。「除外」から「判定方式の事前分岐」への置き
換えが本ドキュメントの主眼である。

### 2.4 入力上限と範囲外の明示拒否

契約の有効範囲は `n < 2^24`（`n` は縮約対象要素数＝行数 `m`）と定める。この範囲を
超える入力に対しては、Metal 実装（`gemm_fp32_strict_into` の bias 勾配縮約経路）・
ホスト参照実装（`reduce_bias_grad_rows_host`）のいずれも **`BackendError::
InvalidArgument` を返し fail-closed に拒否する**。範囲外の入力をホスト `f64` 実装へ
無言でフォールバックする、あるいは Tier A/B のどちらの判定もせず素通りさせる、と
いった経路は設けない。

この方式では「範囲外の入力が拒否されること」自体が受け入れ契約であり、`n = 2^24`
（境界）・`n = 2^24 + 1`（境界超過）を与えて `InvalidArgument` が返ることを機械的に
検査する契約テストで担保する。実装・契約テストの追加は PR #1659 側で行う（本
ドキュメント自体はコードを変更しない。「5. スコープ限定」を参照）。

### 2.5 非有限値の扱い（Tier A の適用条件）

Tier A・Tier B の上界式（実数の誤差上界）は、`y_ref` と `y_metal` の**両方が有限**
である場合にのみ適用する。少なくとも一方が非有限（NaN／±inf）である場合は、実数の
上界式の代わりに次の**クラス一致**を契約とする:

- `y_ref` が NaN ⟹ `y_metal` も NaN でなければならない
- `y_ref` が `+inf`（`-inf`）⟹ `y_metal` も同符号の `+inf`（`-inf`）でなければ
  ならない
- `y_ref` が有限であるにもかかわらず `y_metal` が非有限（またはその逆）は
  **実装のバグ**であり、除外や緩和の対象にはしない

`y_ref` が非有限になるのは、(a) 入力 `x_i` 自体に NaN／±inf を含む場合、(b) 入力は
すべて有限だが `S_ref`（`f64` 累積和）の `f32` downcast 自体が overflow して ±inf に
なる場合、の 2 通りがある。例:

- `[f32::MAX, f32::MAX]`: `S_ref` が `f32::MAX` の表現範囲を超え、downcast で
  `y_ref = +inf`。この場合 `y_metal` も `+inf` が要求される
- `[inf, -inf]`: 入力自体に符号の異なる無限大が含まれ、`S_ref = NaN`（`inf + (-inf)`
  は IEEE 754 上 NaN）。この場合 `y_metal` も `NaN` が要求される
- `[f32::MAX, f32::MAX, -f32::MAX]`: `S_ref` は有限（`f32::MAX`）であり、Metal 側も
  2 の冪 scale（`bias_pow2_floor`）により中間 overflow を経ずに有限値を得る設計の
  ため `y_metal` も有限。この場合は非有限クラス一致ではなく通常どおり Tier A の
  実数上界式を適用する

カーネル側の実装形（列内に非有限値が含まれる場合に IEEE 754 の伝播規則をホスト
`f64` 逐次和と同一のクラス（NaN／±inf のいずれか）に揃える具体的な演算順序・
分岐）は PR #1659 側で規定し、対応する実機テストもそちらで追加する（本ドキュメント
自体はコードを変更しない）。

## 3. C の確定

### 3.1 理論導出（`C = 4`）

実装は 1 出力列につき 1 thread が `n` 行を完全逐次で Neumaier 改良版 Kahan 補償和する
構成であるため、縮約段数は 1 段のみ（スレッド間結合を要しない）である。1 次項
（`u = ε32` 単位）を次の表のとおり計上する:

| 項目 | 上界 | 根拠 |
|---|---|---|
| 補償和自体の誤差（Neumaier。1 段・完全逐次） | `2u` | Higham『Accuracy and Stability of Numerical Algorithms』4.3（Neumaier (1974) の改良版補償和）の標準的な上界 |
| `y_ref` の downcast（`S_ref`〈`f64`〉を 1 回 `f32` へ round-to-nearest） | `1u` | `\|y_ref − S_ref\| ≤ u·\|S_ref\| ≤ u·Σ\|x_i\|`。round-to-nearest の丸め誤差は一般に丸め単位 `u`（相対誤差の上界。ここでは絶対誤差 `u·\|S_ref\|` に換算）であり、**`0.5u` ではない**（旧版の誤り。例 `[1, 2^-24]`: `S_ref = 1 + 2^-24`。`1` の次に大きい `f32` 値は `1 + 2^-23`（`[1, 2)` 区間の `f32` 刻み幅は 23bit 仮数部より `2^-23`）であり、`S_ref` はちょうどその中点 `1 + 2^-24` に一致する。round-to-nearest（-even）によりこの中点は `1` へ丸められ、丸め誤差は `2^-24 = ε32 = u`（`≈ u·\|S_ref\|`。`\|S_ref\| ≈ 1`）となる。すなわち丸め誤差は `0.5u`（`= 2^-25`）ではなく `u`（`= 2^-24`）そのものに達する、`u·\|S_ref\|` が正しい上界であることを示す最小例である。codex-review P2・スレッド `PRRT_kwDOTuUCJc6hvxnm` の指摘。刻み幅・丸め誤差の記述自体の是正はスレッド `PRRT_kwDOTuUCJc6hv2sw` の指摘） |
| 安全余裕（下記 (a)(b) の合計を吸収） | `1u` | `= ε32 · Σ\|x_i\| = 2^-24 · Σ\|x_i\|` |
| **合計** | **`4u`** | **`C = 4`** |

安全余裕 `1u = 2^-24 · Σ|x_i|` が吸収する項は、いずれも具体的な上界を持つ次の 2 つ
に限り（codex-review P2・スレッド `PRRT_kwDOTuUCJc6hv5IK` の指摘を受け、上界を
持たない項をこの一覧から排した。旧版が含めていた「補償項 `c` 自身の丸め等」は
独立の上界式を与えられないため、以下の (a)(b) には含めない）:

- **(a) `S_ref` 自身の `f64` 逐次丸め**: `≤ (n − 1) · ε64 · Σ|x_i| ≤ 2^-29 · Σ|x_i|`
  （`n < 2^24`。「3.3」節）
- **(b) 2 の冪 scale 除算の underflow**: `≤ n · 2^-150 · Σ|x_i| ≤ 2^-126 · Σ|x_i|`
  （`n < 2^24`。「3.4」節）

(a)+(b) の合計は `< 2^-28 · Σ|x_i|`（(a) が支配項で `(b)` は無視できるほど小さい）
であり、安全余裕 `2^-24 · Σ|x_i|` に対し比率 `2^-28 / 2^-24 = 2^-4 = 1/16` と、
余裕の範囲内に収まる。

**2 次項の係数は証明された上界ではなく契約上の規約値**: `n · ε32² · Σ|x_i|`
（Tier A 上界式の 2 次項）は Higham 4.3・Neumaier (1974) が与える漸近記法
`O(n · u²)` に対応するが、これらの文献は本カーネル（2 の冪 scale 併用の Neumaier
補償和）というこの変種に対する普遍的な明示定数を与えていない。したがって、係数
`1`（すなわち `n · ε32²` そのもの）は数学的に証明された上界ではなく、**本契約が
定める規約（定義）**として採用する。採用値の妥当性は、PR #1659 の逐語ホストモデル
実測（観測誤差比の最大値 `2.98e-8`。`n` を `5×10^5` まで振っても他の全被験入力は
`Δ = 0`〈bit 完全一致〉。「3.2」節）を根拠とする。将来、この係数の下で Tier A が
成立しない実機実測入力が見つかった場合は、「2. 2 層契約の定義」の Tier A/B が扱う
「除外」（判定方式の事前分岐）とは性質が異なり、**契約自体（係数・上界式）の
ユーザー再検討**として扱う。有効範囲 `n < 2^24` はこの規約化によっても変更しない。

### 3.2 実測確認（PR #1659 逐語ホストモデル）

PR #1659 の逐語ホストモデル（Metal カーネルの演算列を bit レベルで再現するホスト側
シミュレータ）による実測で、観測誤差比 `|y_metal − y_ref| / (ε32 · Σ|x_i|)` の最大値は
`[2^48, 2^24, 1, -2^48, -2^24]`（Tier B 不成立列の代表例）の `2.98e-8` のみが唯一の
非ゼロ値であり、他の被験入力はすべて `Δ = 0`（bit 完全一致）であった。`2.98e-8` は
`C = 4` が要求する上界（`(4 + n·ε32) ≈ 4`。この列は `n` が小さいため二次項はごく僅か）
を遥かに下回り、`C = 4` は安全側の上界として実測と整合する。

### 3.3 `S_ref` と真値の差

`S_ref` は `f64` による index 順の逐次和であり、無限精度の真値とは一般に一致しない
（結合則が成り立たない浮動小数点演算のため）。両者の差は次の上界を満たす（Higham
4.2 の素朴な逐次和誤差上界。`ε64 = 2^-53`）:

```
|S_ref − S_exact| ≤ (n − 1) · ε64 · Σ|x_i|
```

`n < 2^24` の有効範囲では `(n − 1) · ε64 < 2^24 · 2^-53 = 2^-29`、すなわち
`|S_ref − S_exact| ≤ 2^-29 · Σ|x_i|` であり、Tier A/B が扱う `ε32 = 2^-24` 由来の誤差
（`2^-24` オーダー）と比べて無視できるほど小さい。本契約（Tier A/B）はこの差を丸め
込まず、あくまで `S_ref`（参照実装の出力）を基準として定義する。

### 3.4 2 の冪 scale の underflow 誤差の吸収

「3.1 理論導出」の「2 の冪 scale は誤差項を追加しない」という記述は、商 `x_i/scale`
が exact であることを前提とする。この前提が成り立つ条件と、成り立たない場合（商が
underflow する場合）の誤差が「3.1」節の安全余裕（1u）にどう吸収されるかを以下に示す
（codex-review P2・スレッド `PRRT_kwDOTuUCJc6hvug6` への対応）。

**exact の条件**: `scale` は列内の要素の最大絶対値以下の最大の 2 の冪であるため、
`scale = 2^k`（`k` はある整数）であり、`max|x| / 2 < scale ≤ max|x|` を満たす。
除算 `x_i/scale` は指数部の減算のみで仮数部を変更しない 2 の冪除算であるため、商が
f32 の**正規化数の範囲**（絶対値 `≥ 2^-126`）に収まる限り丸めは発生せず exact で
ある。商が正規化数の範囲に収まる条件は:

```
|x_i| / scale ≥ 2^-126
```

すなわち、列内のダイナミックレンジが `max|x| / |x_i| ≤ 2^126` を満たす要素 `x_i`
については除算が exact である。

**underflow する場合の誤差上界**: `max|x| / |x_i| > 2^126` を満たす要素（商が f32 の
非正規化数域、または 0 へ丸められる要素）については、round-to-nearest における商の
絶対誤差は f32 の最小非正規化数 `2^-149` の半分、すなわち `2^-150` 以下（round-to-
nearest の丸め誤差は刻み幅の半分以下という性質）であり、`scale` を掛け戻した際の
要素あたりの絶対誤差は:

```
|誤差_i| ≤ 2^-150 · scale ≤ 2^-150 · max|x_i| ≤ 2^-150 · Σ|x_i|
```

列全体（最大 `n` 要素、`n < 2^24`）で最悪ケース（全要素が underflow する）を仮定
しても、合計誤差は:

```
Σ|誤差_i| ≤ n · 2^-150 · Σ|x_i| < 2^24 · 2^-150 · Σ|x_i| = 2^-126 · Σ|x_i|
```

（`n < 2^24` の有効範囲を用いた）。

**安全余裕（1u）への吸収**: 「3.1」節のとおり、安全余裕は `1u = ε32 · Σ|x_i| =
2^-24 · Σ|x_i|` であり、この余裕は underflow 誤差（本節・「3.1」節 (b)）に加え
「3.3」節の `S_ref` 逐次丸め（「3.1」節 (a)）の合計を吸収する（(a)+(b) <
`2^-28·Σ|x_i|`。「3.1」節を参照）。上記の underflow 最悪ケース誤差
`2^-126 · Σ|x_i|` 単独でも、余裕
`2^-24 · Σ|x_i|` に対し `2^-102` 倍（`2^-126 / 2^-24 = 2^-102`）という圧倒的な余裕で
収まる。したがって underflow 由来の誤差は安全余裕へ既に吸収されており、Tier A の
上界式（`(4 + n·ε32)·ε32·Σ|x_i|`）は変更しない。

**例**: `[2^127, 2^-149, -2^127]` では `max|x| = 2^127` 自体が 2 の冪であるため
`scale = 2^127`。中央要素 `2^-149`（f32 の最小非正規化数）の商は
`2^-149 / 2^127 = 2^-276` となり、f32 の表現可能範囲を大きく下回るため商は 0 へ
丸められる（underflow）。この要素が失われることによる誤差は元のスケールで
`2^-149`（中央要素自身の絶対値。round-to-nearest の一般上界 `2^-150 · scale =
2^-150 · 2^127 = 2^-23` はこの具体例に対する粗い上界であり、実際の誤差はそれより
遥かに小さい `2^-149` に留まる）である。`Σ|x_i| = 2^127 + 2^-149 + 2^127 ≈ 2^128`
に対し、安全余裕 `2^-24 · Σ|x_i| ≈ 2^-24 · 2^128 = 2^104` は underflow 誤差
`2^-149` を遥かに上回り、Tier A は通常どおり成立する。

## 4. 既存承認との関係

- 2026-09-12 のユーザー承認（イシュー #1566）は「勾配の長軸縮約の Metal 実装形を
  Neumaier 改良版 Kahan 補償和 + 2 の冪 scale とし、`f64` 相当として扱う」という
  実装形そのものの採用を対象とする。本ドキュメントの Tier A/B は、この承認された
  実装形が満たす数値的性質を**形式化**したものであり、新たな tolerance 値を導入する
  ものではない
- Tier B の右辺（`max(1e-3・|S_ref|, 1e-5)`）は REQ-2 の既存承認済み定数（相対誤差
  1e-3・絶対誤差 1e-5）をそのまま使う。Tier A の `ε32 = 2^-24`／`ε64 = 2^-53` も
  f32／f64 の丸め単位という既存の事実であり、いずれも新規の緩和ではない
- **係数 `C = 4` は「どれだけ緩めるか」というポリシー判断ではなく、実装済みカーネル
  の構造（縮約段数 1 + downcast 1 回 + 安全余裕 1u）から機械的に導出した値であり、
  PR #1659 の逐語ホストモデル実測（「3.2」節）と整合する**

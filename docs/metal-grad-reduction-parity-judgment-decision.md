# 勾配の長軸縮約（Metal）の一致判定方式の決定記録（イシュー #1566）

> **状態: 確定（一致判定の 2 層契約自体はユーザー承認 2026-09-12。イシュー #1566）。
> Tier A の係数 `C` は暫定値（安全側 `C=8`）のまま未確定で、PR #1659（イシュー #1566
> 実装 PR）の逐語ホストモデル実測により確定する。spec（fandhe-ai-spec REQ-2）への
> 一般化提案は「6. spec 起票要否」のとおり別途ユーザー承認待ち。**

PR #1659（Metal bias 勾配の resident 化）の codex-review が P1 として、AGENTS.md・
`.claude/rules/coding-rust.md` の当初追記（「REQ-2 統一複合判定を実用入力範囲…で適用し、
`[2^48, 2^24, 1, -2^48, -2^24]` のような…保持範囲を超える人工的相殺は同判定の対象外と
する」）を指摘した（スレッド `PRRT_kwDOTuUCJc6hvjYM`）。指摘の要旨は、「f32 補償和の
保持範囲」が**入力から事前に判定できる述語になっておらず**、実測結果を見てから「この
入力は対象外だった」と事後的に除外することを許してしまう（契約を弱める）というもの
である。本ドキュメントはこの指摘を受け、除外を廃した**事前判定可能な 2 層契約**として
定式化し直す（`docs/backend-metal-splitk-parity-judgment-decision.md` と同型の構成）。

## 1. 背景

### 1.1 対象

勾配の長軸縮約（dw の行方向蓄積・bias 勾配の行方向縮約等）の Metal 実装形は
`AGENTS.md`・`.claude/rules/coding-rust.md` の既存契約（正規化統計・勾配の長軸縮約は
`f64` アキュムレータで統一する。イシュー #1102・ユーザー承認 2026-09-01）に従い
**Neumaier 改良版 Kahan 補償和 + 2 の冪 scale**（`bias_pow2_floor`。列内の要素の最大
絶対値以下の最大の 2 の冪で括り出す。除算・比が 2 の冪同士のため exact であり、
scale/ssq 方式〈正規化統計の二乗和向け〉とは異なり誤差項を追加しない）として実装する。
MSL（Metal Shading Language）は `double` 型非対応のため、この実装形は f32 のみで
構成され、ホスト（CPU）`f64` 蓄積・CUDA `double` 蓄積と**厳密同値にはならない**
（2026-09-12 ユーザー承認済みの事実。イシュー #1566）。

### 1.2 当初案の問題点（codex-review P1）

イシュー #1566 の当初の契約明文化（PR #1666 初版）は「REQ-2 統一複合判定を実用入力
範囲（列内ダイナミックレンジが f32 の 24bit 仮数＋補償項で保持できる範囲）で適用し、
それを超える人工的相殺は同判定の対象外とする」という表現を採った。この表現は:

- 「保持できる範囲」が定量的な述語として定義されておらず、実測して fail した入力を
  見てから「この入力はダイナミックレンジが広すぎたので対象外」と事後的に判定できて
  しまう（契約としての事前拘束力がない）
- REQ-2／`docs/candle-parity-tolerance-contract-decision.md` 等、既存の tolerance
  契約はいずれも「入力から計算できる値」（相対誤差・絶対誤差・スケール付き絶対誤差の
  各 ceiling）で判定しており、「除外」という形の緩和は前例がない

これは `.claude/rules/security.md`「自己修復ループ固有のガードレール」・
`.claude/rules/coding-rust.md`「テスト・ベンチ」節が要求する「バックエンド間数値一致
テストの許容誤差を単独で緩和しない」の趣旨に照らして妥当な指摘であり、本ドキュメント
はこれを踏まえ除外を廃した 2 層契約へ改める。

## 2. 2 層契約の定義

### Tier A（全入力に常に適用・除外なし）

Metal 出力 `y_metal` とホスト `f64` 逐次和を 1 回だけ `f32` へ downcast した `y_f64` の
誤差は、次の上界を常に満たす（Higham『Accuracy and Stability of Numerical Algorithms』
4.3 の補償和誤差上界・Neumaier (1974) に基づく形式）:

```
|y_metal − y_f64| ≤ C · ε32 · Σ|x_i| + O(n · ε32²) · Σ|x_i|
```

- `ε32 = 2^-24`（f32 の丸め単位）
- `C` はカーネルの縮約段数（スレッド内補償和 1 段 + スレッド間結合 1 段 + 最終
  downcast 等）から導出する定数。**現時点では逐語ホストモデルによる実測が完了して
  おらず未確定のため、安全側の暫定値 `C = 8` を用いる**。確定値は PR #1659
  （イシュー #1566 実装 PR）の逐語ホストモデル実測をもって本ドキュメントへ反映する
- `O(n · ε32²) · Σ|x_i|` は 2 次誤差項（`n` は縮約対象要素数）。1 次項 `C·ε32·Σ|x_i|`
  が支配的であることが通常だが、上界としては省略しない

Tier A はどの入力（人工的な相殺を含む）にも常に成立することが要求される。Tier A が
成立しない場合は実装のバグであり、除外や緩和の対象にはしない。

### Tier B（REQ-2 統一複合判定）

REQ-2 統一複合判定（相対誤差 1e-3 未満 または 絶対誤差 1e-5 未満）を厳密ゼロ fail 判定
として適用するのは、**入力から事前に計算できる述語**が成立する列に限る:

```
C · ε32 · Σ|x_i| ≤ max(1e-3 · |S_f64|, 1e-5)
```

- `S_f64` はホスト `f64` による厳密和（真値）
- 左辺は Tier A の 1 次誤差上界（2 次項は無視できるとみなす）、右辺は REQ-2 の絶対誤差
  ceiling（`|S_f64|` が十分大きい場合は相対誤差 ceiling `1e-3・|S_f64|` が支配）
- この述語は列の**条件数** `κ = Σ|x_i| / |S_f64|`（相殺が大きいほど κ が大きい）の
  上限と等価であり、`Σ|x_i|` と `S_f64` の両方を計算する時点（＝実行前）で判定できる

この述語が成立しない列（例: `[2^48, 2^24, 1, -2^48, -2^24]`。`S_f64 = 1` に対し
`Σ|x_i| ≈ 2^49` と極端に大きく κ が非常に大きい）は、REQ-2 統一複合判定の対象から
**除外するのではなく**、Tier A のみで判定する（Tier A は無条件に成立が要求されるため、
安全性は失われない）。

### 除外方式との違い

当初案の「保持範囲を超える相殺は対象外」は、実測後に個々の入力を見て事後的に「対象外
だった」と判定する余地を残していた。Tier A/B は逆に、**実行前に入力（`Σ|x_i|` と
`S_f64`）だけから Tier A・Tier B のどちらで判定すべきかを一意に決定できる**。かつ
Tier B 不成立の列も無契約になるわけではなく、常に Tier A（より緩いが無条件の上界）で
判定される。「除外」から「判定方式の事前分岐」への置き換えが本ドキュメントの主眼である。

## 3. 既存承認との関係

- 2026-09-12 のユーザー承認（イシュー #1566）は「勾配の長軸縮約の Metal 実装形を
  Neumaier 改良版 Kahan 補償和 + 2 の冪 scale とし、`f64` 相当として扱う」という
  実装形そのものの採用を対象とする。本ドキュメントの Tier A/B は、この承認された
  実装形が満たす数値的性質を**形式化**したものであり、新たな tolerance 値を導入する
  ものではない
- Tier B の右辺（`max(1e-3・|S_f64|, 1e-5)`）は REQ-2 の既存承認済み定数（相対誤差
  1e-3・絶対誤差 1e-5）をそのまま使う。Tier A の `ε32 = 2^-24` も f32 の丸め単位という
  既存の事実であり、いずれも新規の緩和ではない
- **未確定なのは係数 `C` の具体値のみ**であり、これは「どれだけ緩めるか」という
  ポリシー判断ではなく、実装済みカーネルの構造（縮約段数）から機械的に導出される値
  である。実測により確定するまでは安全側（大きめ）の暫定値を使う方針とする

  （AGENTS.md・`.claude/rules/coding-rust.md`・CLAUDE.md の docs 索引のみを変更する）

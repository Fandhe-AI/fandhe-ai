## 2. 改訂提案の文案（spec リポ向け。未起票）

タイトル案: `docs(requirements): ROCm 契約「公開 API は非破壊（追加のみ）」に Device の承認済み破壊的変更の例外を加える（実装リポ Fandhe-AI/fandhe-ai#3715・#3714）`

### 提案 1（要）: `:405` の契約

旧文（逐語）:

```markdown
公開 API は非破壊（追加のみ）とする
```

新文（案）:

```markdown
公開 API は追加のみとする。ただし、facade の `Device` への ROCm variant の追加と、それに伴う `Device` への `#[non_exhaustive]` 付与に限り、所有者の承認を得た場合に 0.x の minor 版（0.14.0）で破壊的変更として許容する。移行ノート（実装リポ `docs/migration/0.14.0.md`）を必須とし、自己修復ループ（ガードレール判定）の自動適用対象にしない。他の型は追加のみを維持する
```

理由:

- `Device` に非破壊で variant を足す形がない（`docs/backend-rocm-device-exposure-decision.md` §3 の案 C・D が不成立。#3714 §3.1〜§3.3）
- 0.x の minor での破壊は版上は合法で、先例がある（0.1.0→0.2.0・0.2.0→0.3.0）
- 文中は「所有者の承認を得た場合に限る」とし、承認が無い間は発効しない

### 提案 2（軽微・任意）: `:236`・`:238`・`:383` の基準版

旧文（逐語）: `fandhe-ai =0.10.0` の公開 API（`:236`・`:238`）／出荷済み 0.10.0 の公開面（`:383`）

新文（案）: 出荷済みの公開 API（基準版は実装リポ `docs/api-compat-0.14.0-decision.md` を正とする）

理由: 0.10.0 は 0.13.0 まで 3 版古い。意味は変えない。所有者が「不要」と判断してよい。

### 提案 3: 改訂履歴の行

```markdown
| <日付> | ROCm の「承認時に固定する契約」の「公開 API は非破壊（追加のみ）」に、`Device` の承認済み破壊的変更の例外を追加（実装リポ Fandhe-AI/fandhe-ai#3715・承認 <承認後に記入>）。 |
```

### 不変事項

REQ-2 の統一複合判定・tolerance・baseline・FMA 契約、REQ-8 の下限、ガードレール 5 条件と閾値、ポリシー除外リスト、Won't 判断、承認済みのスコープ件数、ROCm の除外事項上の格上げ状態は変更しない。

- (b)（破壊的変更を出さない）: 提案を出さない。`:405` は整合する。提案 2 の基準版整理だけを任意で残す

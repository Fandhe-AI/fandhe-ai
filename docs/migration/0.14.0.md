## 記入規則

1. 1 つの PR は自分の項目の行だけを書く。ほかの行を整形しない。競合したら rebase して双方の変更を残す
2. 状態の値は「未記入」「記入済み（PR 番号）」「対象外（承認 URL）」のどれかに限る
3. 承認は、所有者の回答コメントの URL と日付だけを事実として書く。得ていない承認は書かない
4. 測っていない値は「未実測」のまま残す。Linux や M4 Max 開発機の代替値で埋めない
5. 実機のホスト名は書かず、`<cuda-node>`・`<metal-node>`・`<rocm-node>` で表す
6. 破壊的変更の PR は、件名を `type(scope)!:` にし、本文に `BREAKING CHANGE:` を書く（`.claude/rules/conventional-commits.md`）
7. 部品だけの PR は `Refs #N` を使う。`Closes #N` は完了条件を満たした PR だけが使う
8. 公開名は実装 PR が書く。ここでは予定の名前を推測で書かない
9. 破壊的変更として載せてよいのは、節 2 の 1 件だけ。ほかの項目で破壊的判定が出たら、`docs/api-compat-0.14.0-decision.md` §8 手順 3 に従って所有者へ戻し、この文書には書かない
10. 本書はガードレールの「公開 API 非破壊」判定を迂回する根拠や除外ルールではない。承認済みの破壊的変更は、人間が起こすレビュー済みの PR で入れ、自己修復ループの自動適用対象にしない（同 §7）
11. 対象外になった項目（# 1・# 16、`CtcLoss`、`Inv`・`Solve`・`SlogdetLogAbsDet`）は載せない

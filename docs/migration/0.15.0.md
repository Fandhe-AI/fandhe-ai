- 対象: `fandhe-ai 0.14.0` から `0.15.0`（lockstep の全公開クレート）
- 状態: **バンプ時点の記録**（イシュー #4174）。公開は #4175（所有者の明示指示が要る）。公開日・タグは含まない
- 範囲: 公開 API は facade（`docs/compat-api-scope.md` §0）。内部クレートの変更は、facade 経由で利用者に見える場合だけ載せる
- facade の公開 API の追加・削除・シグネチャ変更はない（下記 2 の内部クレートの変更は facade の公開面を変えない）
- `=0.14.0` で固定している利用者（`scripts/bench/framework-compare/` の第 9 区分ピンなど）は、ピンを上げるまで影響を受けない（ピン更新は #4176。所有者承認が要る）

## 1. 既定の変化

出力の値を変える変化ではない。既定の経路・stream・スレッド分配が変わる。

### 1.1 CUDA: 推論 Graph が既定 ON（#4167・PR #4290）

- `crates/backend-cuda/src/graph.rs:673` の `INFER_GRAPH_DEFAULT_ENABLED` が `true` になった。根拠は #4163 の測り直し（RULE.v3）の ADOPT と所有者承認
- **学習を含む全ての CUDA 利用者に波及する**: `crates/backend-cuda/src/device.rs:414-422` の `CudaDevice::new` は、推論 Graph の要求（`infer_graph_stream_requested`）を OR で created stream の選択条件に含める。既定 ON のため、同じ GPU の CUDA デバイスは学習の経路も含めて、既定で created stream（`Legacy` ではない）で動く。stream 種別は ordinal ごとに sticky で、最初のデバイス初期化時に決まる
- 出力は bit 同一（#4290・#4291 の実機確認）
- opt-out: 環境変数 `FANDHE_AI_CUDA_GRAPH_INFER=0`（`1`／`true` 以外）、または facade の `set_cuda_graph_infer_enabled(false)`（`crates/facade/src/lib.rs:3768` が呼ぶ `graph::set_infer_graph_enabled`）。優先順位は API 明示 > 環境変数 > 既定。API は最初の CUDA デバイス初期化より前に呼ぶ（遅れると stream が確定済みで効かない。`graph.rs:696-705`）
- **学習の速さへの影響（#4299 で確かめた）**: #4168 の前後比較では、G-CUDA-TRN（CUDA の学習・size 64・reuse）だけ after が 5/5 遅かった（腕比の中央値 1.007）。#4299 の 4 腕 A/B（GB10・16 ラウンド・2026-11-14）では、この後退は再現しなかった。判定 R1 は「逆向き」で、B/A（0.15.0 相当 ÷ 0.14.0）の中央値は 0.993、> 1 は 1/16 ラウンドだった。created stream の腕（B・D）の方が、legacy の腕（A・C）より約 0.3〜0.8% 速い（D/A の中央値 0.992、B/C の中央値 0.997）。checksum はすべて一致した（`docs/perf/logs/diag-4299-cudatrn-stream/gb10/judge-4299-gb10.md`）。opt-out は推論 Graph を使わない場合のためのもので、学習の速さのために使う必要はない

### 1.2 CPU: SME 既定 ON と推論スコープの jpw1（#4165・PR #4284）

- SME 経路を既定 ON にした（`crates/backend-cpu/src/gemm_blis/mod.rs:3561` の `SME_PRODUCTION_ENABLED` = `true`。aarch64 限定）。適格形状は M≥256・N≥256・K≥64（`mod.rs:3572-3574` 付近・`sme_small_sched.rs:36` の `BAND_MIN`）。SME 非搭載ホストは従来どおり NEON で、出力 bit は不変
- 小形状（N=256 級）のスレッド数・分配の機構 t4-jpw1（#4162）を結線した（`sme_small_sched.rs:38`）
- 推論スコープ内の jpw1 は **aarch64 Linux だけ**既定 ON、ほかは OFF（`crates/backend-cpu/src/gemm_blis/infer_scope.rs:24-26`）

### 1.3 Metal: steel の経路を N≥1024 で既定 ON（#4166・PR #4255）

- N≥1024 限定の steel 候補 T0U-LU-FB を、M4Base の正方 1024／2048／4096 へ結線した（`crates/backend-metal/src/tile.rs:1802` の `STEEL_LARGE_N_ENABLED` = `true`）。構築に失敗した場合は表の経路で組み直す（#4267）

## 2. 内部クレートの破壊的変更

- `fandhe-ai-backend-cpu` の `microkernel::*::kernel_unchecked*`（SME・AVX2・AVX-512）を `pub(crate)` にした（#4285。例: `crates/backend-cpu/src/gemm_blis/microkernel/sme.rs:352`・`avx512.rs:152`）。内部クレートの変更のため semver 上は破壊的だが、facade の公開面は変わらない。`backend-cpu` を直接依存にしている場合だけ影響する（境界検査を持たない `unsafe fn` を外へ出さないための変更）

読み違い注意 1（burn の CUDA は TF32）: burn（cubecl）の CUDA matmul は f32 入力を常に TF32 へ降格し、無効化する公開スイッチがない（docs/analysis/burn-cubecl-cuda-matmul.md）。fandhe-ai の既定は FP32 strict（docs/cuda-gemm-default-precision-decision.md・#3262 で維持）。burn が最速相手の CUDA セルは、精度クラスが違う比較である（burn は u=2^-11 の TF32、fandhe-ai は u=2^-24 の FP32）。参考に、fandhe-ai を TF32 opt-in にした実測は G-CUDA-G4096 で対 burn 1.17×（0.11.0・推定。docs/perf/loss-attribution-matrix.md §10.7）。この opt-in は既定 OFF で、上の表の判定には含めない。

出典: registry ピン fandhe-ai =0.12.0 で、各ラウンドに run_all_cuda.sh（fandhe-ai／candle／burn）→ 追加計測（CPU GEMM の reuse N=256〜4096 と N=4096 の fresh 3 種）→ bench_py.py（PyTorch cu130 CPU／CUDA・TensorFlow CPU・SciPy）を続けて実行し、5 ラウンドの中央値を採った（{gb_load}）。5 ラウンドの run 別の対戦相手比は gen_0120.out（本ディレクトリ）に出している。run_all_cuda.sh の TF32 opt-in スイープ（#1983。fandhe-ai／candle の --tf32 行）は f32 同士の判定から除外し、下の「エンジン単体の対照」節に参考値として載せる（burn は TF32 が既定でその行しかないため f32 表にも従来どおり載る）。burn CUDA GEMM（TF32 既定降格）は承認済みの精度クラス（burn cuda の tf32: true 行のみ u=2^-11 で第 3 救済項を評価。#1989 承認・#2046 実装・fandhe-ai 行と candle 行は u=2^-24 のまま不変）により 5 形状とも有効セルで、△ の数字は精度クラス TF32 の第 3 救済項で救済した要素数（0.9.0 版の初出時は判定不能扱いで、#1988 版から有効セル）。fandhe-ai は f32、burn は TF32 という精度差を含む比較である点に注意。{gb_inv_note}判定不能セルは打ち消し線で示し順位に含めない。TensorFlow 2.21.0 は GB10 では CPU のみ計測（CUDA 列は未計測で「—」）。CUDA GEMM の N≤2048 で fandhe-ai の reuse が fresh より遅いのは既知の傾向（reuse は matmul ごとにホスト実体化と checksum を含む計測窓のため。docs/perf/cuda-gemm-reuse-phase-breakdown.md）で、判定列は規則どおり reuse のまま。

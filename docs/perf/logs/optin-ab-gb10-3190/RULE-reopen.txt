2. B5 (境界述語の事前計算。元 RULE.txt 8 の文言どおり。以下は具体化だけ)
  - base = 230937f5f (元 RULE.txt を固定したコミット)、head = base + on-boundary-predicate.patch。
    kernels_mma.rs の MMA_F16_BODY とソース証跡テストの needle だけを変える。patch はリポジトリに収録するだけで、適用は GB10 上の計測専用 clone に限る。
    230937f5f から origin/main の間の backend-cuda 差分が tests 以外で空であることを記録する。
  - patch の設計: A の行述語 (gr < DIM_M) と B の列述語 (gc < DIM_N) は k0 に依存しないため、グループごとに入口で 1 回だけ評価してビットに詰め、
    K 方向の述語は各 stage で評価してビットと AND する。エピローグは入口で 16 ビットの epilogue_valid を 1 回計算し、書き戻しはビット参照のみ。
    クランプ済みアドレス計算 (gr_c/gc_c)・範囲外ゼロ充填・__half2 ペア store と c0 単独フォールバックの構造は変えない。
    境界検査を省く変種は採らない。
  - 前提ゲート (a): base・head の両方で次を実行する (--nocapture は付けない)。
      cargo test -p fandhe-ai-backend-cuda --release --test cpu_cuda_mma_parity --test gemm_mma --test parity_nonregression
        --test specialized_mma_parity --test gemm_auto --test dispatch_boundary -- --ignored --test-threads=1
      cargo test -p fandhe-ai-backend-cuda --release --lib kernels_mma
    head で FAILED かつ base で ok のテストが 1 件でもあれば前提不成立。base でも FAILED のものは区別して記録し、後退とは数えない。
    base と head のテスト集合が一致しなければ FAIL (fail-closed)。
  - 前提ゲート (b): 腕ごとに mma_ptx_dump で PTX をダンプし、本番構成 (mma_f16_base.ptx) を ptxas -arch=sm_121 -v に掛けて
    registers・stack frame・spill stores/loads・lmem を記録する。head の lmem または stack frame が base より増える、
    または head の spill が 0 でなければ前提不成立 (undetermined)。registers は記録のみで判定に使わない。
  - 前提ゲートのどちらかが不成立なら TFLOPS 計測へ進まず undetermined を記録して終える。
  - 計測: gemm_mma_bench を腕ごとに 5 プロセス独立で起動する。奇数 round は base -> head、偶数 round は head -> base。
    各プロセスの前に専有ゲート (load1 < 1.0 かつ GPU 0%。30 秒間隔・最大 30 分) を通す。1 回でも不成立なら系列は参考扱い (undetermined)。
    判定値は mma_f16_tflops 列の size 512/1024/2048/4096 だけ。判定式は元 RULE.txt 8 のとおり
    (全形状で head の 5 run 中央値 >= base かつ 1 形状以上で 5/5 run 一貫改善 -> 採用候補、いずれかの形状で 5/5 一貫後退 -> 不採用、それ以外 -> undetermined)。
    「5/5 一貫」は round 対 (同じ round 番号の base と head) の比較で、全 5 対が改善 (後退) であること。
    集計は aggregate_b5.py (python3 -I。--self-test あり。欠損・round 数 != 5・非有限値・未マスクは FAIL)。
  - 採用候補になっても main のカーネルは変えない。本番カーネルへの導入は #537 で別途行う。

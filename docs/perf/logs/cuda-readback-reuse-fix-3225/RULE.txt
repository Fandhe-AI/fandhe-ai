  次回ぶんの宛先 Vec<f32> を非ゼロ sentinel で確保・事前タッチしておく。次の readback は取り出して使う。
  worker は CUDA に触れない。新規 unsafe なし。f32 のみ（f16 など他型は従来経路）

[セル]
- gemm cuda の reuse／fresh × N=256/512/1024/2048/4096（10 セル）。run_ab_readback_prefetch_cuda.sh
- 主判定セル: reuse N=512/1024/2048/4096、fresh N=4096（ratio <= 0.95 を要求）
- ガードセル: fresh N=512/1024/2048（ratio <= 1.03 を要求）
- N=256（reuse・fresh）: プール対象外でコード経路は同一。record_only の非後退確認で、判定に使わない

[計測]
- 5 round 固定（AB_ROUNDS=5 以外は拒否）、プロセス独立起動、round ごとに起動順を反転
- run の差し替え・追加起動はしない。同一 label の既存出力があれば停止する
- 各セルの ratio = median(after) / median(before)（5 run の中央値どうし。単位は bench-fandhe の median_s）
- 同一バイナリ・同一 HEAD（bin の sha256 を manifest に記録。.rev-stamp を回収して git archive の指紋と突合する）

[checksum]
- 全 run・全腕で完全一致（--require-checksum-exact）。不一致は fail-closed で REJECT
- N=1024/2048/4096 は既知値（-1855.597736／-6016.774008／-25768.747284）と 1e-5 以内であること

[判定]
- ADOPT: 専有ゲート（AB_LOAD_GATE_MODE=exclusive。load1 < 1.0 かつ GPU 使用率 0% を 3 サンプル連続）を
  通過し、主判定セルの全てで ratio <= 0.95、ガードセルの全てで ratio <= 1.03、checksum 条件を満たす
- REJECT: 専有ゲートが成立した系列で、いずれかの条件を満たさない
- undetermined: 専有ゲート不成立（record_only を含む）・取得不能・GB10 に到達できず未計測
- しきい値・定数を事後調整して再計測しない
- 後退したセル（ratio > 1.00）は判定に関わらず全て併記する

[事前表明する期待値（仮説。実測ではない）]
- reuse N=512〜2048: 背景の事前タッチが次の反復の checksum・H2D・カーネルと重なり fresh 並みに近づく

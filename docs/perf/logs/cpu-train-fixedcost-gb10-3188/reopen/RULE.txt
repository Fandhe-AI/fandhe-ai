3. H4 診断（cpu_reuse_device_update_h4_diag.rs の cpu_reuse_device_update_h4_phases）:
   - 系列 multi = RAYON_NUM_THREADS 未設定（本番条件）、系列 single = RAYON_NUM_THREADS=1。run ごとに交互の
     独立プロセス、各 5 プロセス。single は書き手コアの帰属判定用の 1 点差分であり、スレッド数最適化の
     スイープではない（先行 RULE の対象外項目とは目的が異なる）。
   - 各プロセス: warmup 20、計測 20 反復 x 4 ラウンド、in-situ 2 腕はラウンドごとに順序反転。n=80/セル。
   - 代表値 = 各セルの run ごとの median_s の 5 run 中央値（min-max 併記）。
   - 記号: T=insitu_direct/device_update、P=insitu_probe/prologue_probe、R=insitu_probe/after_probe、
     K=standalone/sgd_kernel（hot）、S=standalone/stage、Kc=standalone/sgd_kernel_cold、
     Zh=standalone/zip_hot、Zx=standalone/zip_xcore。
   - probe の限界: P は momentum 不一致エラーの文字列 format! を含むため僅かに過大。
   帰属規則（aggregate_h4.py が機械適用）:
   1) 加算性: |P+R-T| <= 0.15*T。不成立なら分解は参考扱いで判定は「未確定」。
   2) H4' = T-(K+S)。
   3) H4a(prologue)=P、H4b(in-situ カーネル超過)=R-(K+S)。H4' の 50% 以上を占める項を「支持」、届かなければ「未確定」。
   4) H4b が支持された場合のみ状態の説明を付ける。x=R-S を、cold=Kc と xcore=K+(Zx-Zh) の各候補と比べ、
      ±25% 以内で x に最も近いものを「整合」、どちらも入らなければ「未確定」。
   5) 書き手コア: (T_single-K_single) <= 0.5*(T_multi-K_multi) なら「マルチコア由来の状態を支持」、そうでなければ
      「非支持」。single が負荷ゲート未通過なら「判定なし」。
   6) checksum（in-situ 2 腕の最終 params、standalone 4 腕の最終 params の bit 一致）の不一致、n 不一致、
      セル欠落、ツリー指紋・.rev-stamp の不一致は系列を無効にする。

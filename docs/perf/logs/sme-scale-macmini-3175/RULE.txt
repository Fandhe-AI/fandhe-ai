事前登録規則（イシュー #3175 / 親 #3174）
固定日時: 2026-10-20 (UTC 日付。計測開始前に本ファイルを単独コミットする)
目的: Mac mini（Apple M4）での SME の多スレッド頭打ちの有無と、micro-call あたりの
      smstart／smstop 固定費を測る。診断のみ。本番コード・既定値・tolerance・FMA 契約は変えない。
      結果は #3176・#3230 以降の判断材料であり、本 PR では何も切り替えない。

1. 機体
   Mac mini（Apple M4・4P+6E・10 コア）。チップ・macOS・rustc・perflevel・FEAT_SME・.rev-stamp
   を env_info.txt に記録する。M4 Max の値とは直接比べない。

2. 形状
   主判定: (256,256,128)・(512,512,256)・(1024,1024,512)・(2048,2048,1024)。
   解釈: Issue は「§5.2 の 4 形状」と書くが、cpu-gemm-sme-fmopa-microkernel.md §5.2 の表は
   7 形状である。§5.4.1 R4 の採用候補領域（min(m,n)>=256 かつ k>=128）に入るのは上の
   ちょうど 4 形状なのでこれを主判定とする。境界点 (256,256,64) は #2118 の対象なので除く。
   参考（頭打ち判定には使わない）: (64,256,784)・(784,256,64)（MNIST 規模 train の L1）。

3. スレッド数・run 数
   RAYON_NUM_THREADS ∈ {1,2,4,10}。1 プロセス 1 スレッド数。採用値は出力行の num_threads= を正とし、
   環境変数・ファイル名・ゲートログと食い違えば fail-closed（集計を止める）。
   5 run（独立プロセス）。run ごとにスレッド数の起動順をローテーションして順序偏りを均す。
   run の差し替え・追加起動はしない。
   プロセス内計測: 既存 run_candidates_interleaved（ウォームアップ 3・10 反復の中央値）。

4. 負荷ゲート
   各プロセス開始前に load1 < 5.0 になるまで 30 秒間隔で最大 30 分待つ。
   (#1587 の 8.0 は 16 コア機向け。コア数比で 10 コアは 5.0。前例より厳しく、緩めていない。)
   取れなければ unavailable。全プロセスが通過したときだけ正式系列、それ以外は参考系列と明記する。

5. 頭打ちの判定（主 4 形状ごと。G(T)=SME の 5 run 中央値 GFLOPS、S(T)=G(T)/G(1)）
   S(4) < 1.25  -> 頭打ちあり（P クラスタ内で伸びない）
   S(4) >= 2.0  -> 頭打ちなし
   その間        -> 部分的
   G(10)/G(4) も記録（判定なし。E クラスタの SME ユニットが加わる効果）。
   総合の見出しは (2048,2048,1024) で出し、残り 3 形状との一貫性を併記する。
   NEON も同じ表（S_neon(T)）を出す。
   第三者実測との比: max_T G(T) / 2008 GFLOPS を形状ごとに記録（2008 はリポジトリ外の値。合格ラインにしない）。

6. smstart／smstop 固定費（テスト sme_microcall_fixed_cost_probe。単スレッド）
   SmeKernel::run を kc_len ∈ {0,1,2,4,8,16,32,64,128,256} で、各点 1 バッチ約 1 ms 以上、
   21 バッチの 1 呼び出しあたり ns 中央値。
   主値: kc=0 の ns/call（直接計時）。補助: kc>=1 で t(kc)=c+s*kc を最小二乗した切片 c・傾き s
   （512 flop / s から定常 GFLOPS）。NeonKernel も同様に測り C タイル出し入れの参考値とする。
   固定費の中身: current_thread_capable 検査（SVL・TPIDR2_EL0）＋長さ検査＋smstart＋C 16 行 ld1w/mova
   ＋ZA0 16 行 mova/st1w＋smstop。新規 asm! を足せないので smstart／smstop だけの分離はできず、
   この値は「1 組の固定費の上限」として扱う。
   適用: (64,256,784) の micro-call 256 組（=4*16*4）×固定費が SME GEMM 実測時間に占める割合を各 T で出す。
   参考（判定外・省略可）: sme_vs_neon_ab_r4_grid を T=1 で 5 run し t=F+calls*c0+calls*k*c1+m*k*p の
   最小二乗で c0 を参考値として記録する。

7. 単スレッド NEON と P／E 分離
   T=1 の NEON 中央値 GFLOPS を記録。P/E 分離は taskpolicy -b（QoS background。E コア側で動くが
   pinning ではなく種別は保証されない）で系列 C を取る。使えない、または E 側と P 側の中央値比が
   0.8〜1.25 なら「分けられなかった」と記録する。E 系列は SME も残す（第三者 E クラスタ約 360 GFLOPS との比較用）。

8. 不変事項
   本番定数（SME_PRODUCTION_ENABLED・SME_MIN_*・MC/KC/NC 等）・tolerance・FMA 契約は変更しない。
   新規 unsafe・asm! を足さない。ログは上書きしない。計測後に本規則を緩めない。

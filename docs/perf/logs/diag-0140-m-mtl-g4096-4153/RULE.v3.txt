3. 計測手順
  ラウンド数は PARAMS の rounds（既定 5）。各ラウンドの前にゲートを通す: hw-lock を取得し、load1 < 3.0 を 30 秒間隔で最大 30 分待つ。計測中にビルド・集計・転送を並走させない（ゲート通過後に cargo を呼ばない）。
  ゲート不通過は gate.txt に TIMEOUT と記録し、そのラウンドを正式系列から外す（status=partial・確度は常に低・表題は「参考」）。
  round の状態は gate.txt の 1 語目（PASS／TIMEOUT／INVALID）だけで伝え、PASS 以外は正式系列から外して系列は partial で集計を続ける:
    INVALID にするもの: load1 が数値でない（ゲート）、ゲート通過後に run_round.sh が非 0 で終わった（腕・診断テスト・マスクの失敗、INT・TERM・HUP）、
    変換で検出した GEMM 区間の本数不一致・区間の重なり・ROUTE_ACTUAL≠Classic・DIAG_BITEQ≠true（to_values_4153.py）。
    INVALID の記録に限り gate.txt の 1 行目を書き換え、元の行は「# was: 」付きで残す。INVALID の round は values.tsv を作らない。
    それ以外の不整合（RULE・AUX・sha256・入力の欠落・重複・解釈不能など。README の「round の状態」）は hard で、系列全体の集計を止める。
  ラウンド内の順序: 段は (a) → (b) → (c) の順に固定し、(a) をすべて終えてから (b)、(b) をすべて終えてから (c) に進む
  （framework ごとに段をまたいでまとめない。trace 下と trace なしの窓で熱状態をそろえるため）。奇偶の入れ替えは (a)・(b) の各段の中の
  framework の順だけで、奇数 round は fandhe → candle、偶数 round は candle → fandhe。framework 内の順と (c) の順は入れ替えない。
    (a) trace なしの窓: fandhe reuse・fandhe fresh・candle gemm（fresh。スコアボードの相手値と同じ）・candle gemm-transfer-split（transfer_excl）
    (b) xctrace（Metal System Trace）の腕: fandhe reuse・candle gemm-transfer-split。GPU 実行区間の表を export する（AUX の xctrace が unavailable なら取らない）
        GEMM 区間は対象プロセスの継続時間 ≥ gemm_interval_min_ms の区間とし、本数が「先行分＋warmup＋iters＋後続分」と完全一致しなければ INVALID
        （fandhe は先行・後続 0。candle は先行＝転送込みの warmup＋iters、後続＝checksum 検証 1）。余分な区間の許容枠は設けない:
        継続時間だけでは余分な区間が先頭・途中・末尾のどこにあるかを特定できず、許容すると測定スライスが黙ってずれるため。
        余分な区間が出て INVALID になった場合の扱いは RULE.v2.txt で抽出規則ごと定め直す。同一プロセスの区間が重なる表も INVALID。
        件数の一致は並びの正しさまでは保証しない（GEMM の欠落と余分な区間が同数なら検出できない）
    (c) 診断テスト: gemm_window_route_precheck（ROUTE_ACTUAL=Classic と bit 一致の確認）と gemm_reuse_phase_diag_production_batch（kernel_gpu＝GPUEnd−GPUStart）
  各ステップ（(a) の 4 本・(b) の 2 本・(c) の 2 本）の間に 30 秒の待ちを入れる（最初の前と最後の後には入れない）。
  実行したステップ名と開始時刻を raw/order.txt に残す。candle の純カーネル時間は Rust 側から GPU タイムスタンプを取れない（objc2-metal の直接依存追加には所有者承認が要る）ため、外部計器 xctrace で取る。
  run の差し替え・追加・除外・上書きは禁止。再実行は別ラベルとし、旧系列を残す。
  到達不能な量は unavailable と記録し、推定値で埋めない（values.tsv にも書かない）。
  保存物: round{i}/{gate.txt, values.tsv, aux.tsv, raw/（order.txt を含む）}・env/。変換手順は README と to_values_4153.py。

4. 診断式（docs/perf/loss-attribution-matrix.md §10.1 から転記。単位は ms）
  入力量: fandhe_window・fandhe_fresh_window・opp_window・fandhe_pure_kernel・opp_pure_kernel
  F1 = opp_window ÷ (fandhe_window − fandhe_pure_kernel + opp_pure_kernel)
       純カーネルの時計タグ（clock 列）を両側で揃える（本診断は両側とも gpu_trace）。揃わなければ F1 は比較不能とし、境界を併記する。
  F2 = opp_window ÷ fandhe_fresh_window
  観測比 = opp_window ÷ fandhe_window（スコアボードの比との整合確認用）
  補助（attrib_4153.py。aggregate_diag.py の判定には使わない）:
    ΔW = fandhe_window − opp_window、ΔK = fandhe_pure_kernel − opp_pure_kernel、kernel_share = ΔK ÷ ΔW
    kernel_share ≥ kernel_share_threshold なら「カーネル側が主」、未満なら「窓側が主」。ΔW ≤ 0 は差なし（判定不能）。
    trace_perturbation = |traced ÷ untraced − 1|（fandhe の reuse 窓と candle の transfer_excl の両方）。最大が perturbation_max を超えたら確度低。
    cross_check_rel = |fandhe_pure_kernel(xctrace) − kernel_gpu(診断テスト)| ÷ kernel_gpu。cross_check_max を超えたら確度低。
    全ラウンドがゲート PASS で、全ラウンドで同じ側に入り、摂動・照合がいずれも上限以内なら確度高、それ以外は低。
    xctrace unavailable では純カーネルを取らないため、帰属は「判定不能(純カーネル unavailable)」（確度低）、摂動・照合は unavailable とし、
    attrib.tsv の fallback_note に「F1 未計測・F2 だけで分類した」旨を出す。

5. 判定の分類先と規則（優先順位つき。aggregate_diag.py の classify と同一）
  分類先: 自分たちの制約／ハードの上限／計測窓の定義／分類保留
  (1) formulas に F2 があり、F2 の run 間中央値が reach_threshold 以上なら「計測窓の定義」。
  (2) そうでなく F1 があり、時計が揃っていて、F1 の run 間中央値が reach_threshold 以上なら、
      kernel_owner=hardware は「ハードの上限」、kernel_owner=constraint は「自分たちの制約」。
      kernel_owner は測る前に宣言する。本セルは constraint（根拠: 相手は閉源 MPS ではなく candle の公開 steel シェーダ。candle は function constant align_M/N/K で境界検査なしのロードを使う〈docs/analysis/candle-metal-01.md 204〜210 行・245 行〉が、fandhe は REQ-8〈coding-rust.md「カーネル実装の境界検査」〉により手動境界検査を保つ）。事後に動かさない。
  (3) それ以外は「分類保留」。理由欄に「どれも届かない（残差は固定費など別区間。別診断へ）」または「F1 の時計不一致」を書く。
  フォールバック: xctrace が使えない、または GPU 区間が 0 行だった場合は AUX の xctrace を unavailable とし、PARAMS の cell 行を formulas=F2 だけで固定する。
    aggregate_diag.py は AUX を読まないため、xctrace と formulas の組は to_values_4153.py・attrib_4153.py が検査する
    （available ⇔ formulas=F1,F2、unavailable ⇔ formulas=F2。食い違えば止まる）。
    F1 は計測しない。分類は上の規則を F2 だけで適用する: F2 の run 間中央値が reach_threshold 以上なら規則 (1) で「計測窓の定義」、
    未満なら規則 (3) で「分類保留」。後者の理由欄は aggregate_diag.py の固定文言「どれも届かない（残差は固定費など別区間。別診断へ）」になるが、
    F1 を測っていないため「自分たちの制約／ハードの上限」は判定していない（F2 が届かないことだけを表す。attrib.tsv の fallback_note に明記される）。
    F1 を宣言しないので「F1 の時計不一致」の理由にはならない。確度は下の規則どおり。
    壁時計境界の F1(b)（candle transfer_excl 対 fandhe encode＋commit_wait。§12.6(b) と同じ境界）は README に参考として併記するだけで values.tsv には混ぜない。
  確度:
    高: 全ラウンドがゲート PASS（status=formal）かつ、判定に使った式の run 別値がすべて閾値の同じ側
        （最小 > 閾値、または最大 < 閾値。境界ちょうどはまたぐ扱い）かつ、formulas に F1 を宣言した場合は時計が揃っている
        （F1 を宣言しないフォールバックでは時計の条件は課さない。分類保留でも F2 の run 別値がすべて閾値未満なら確度は高になる）。
    低: 上記以外。理由欄の先頭に「確度低」を付ける。
  ドリフト: 観測比の中央値が PARAMS の scoreboard_ratio から 10% を超えて乖離したら記録する（判定は変えない）。scoreboard_ratio=0.88 は unreached_0140.tsv の転記で、窓の中央値同士の比 0.871（64.379 対 56.103）との差は README に注記する。

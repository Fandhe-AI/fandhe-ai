0. 位置づけ
  - 目的: N=256 (Mac mini の CPU GEMM) で SME 経路のスレッド数と 2D 分配 (jobs_per_worker) を変えると速くなるかを、事前登録した A/B で判定する。
    根拠はすでにある実測だけを使う: docs/perf/cpu-sme-thread-scaling-macmini.md §2・§3 (#3175: (256,256,128) の SME は T=4 が最大、T=10 は 0.90 倍)、
    docs/perf/logs/sme-default-on-ab-3232/aggregate-macmini.md (gemm 256 の SME ON は PyTorch 比 0.888 / 0.893)。#4151 の区間別内訳の結果を見てから腕を選ばない。
    #4151 の結果が固定時点より後に main へ入った場合は、参考の文脈として末尾へ追記するだけにし、腕の組は変えない。
  - 前例: docs/perf/logs/sme-default-on-ab-4156/RULE.txt (#4156)。語彙 (FAIL / REJECT / ADOPT / undetermined) と 5 round・5/5 一貫性・checksum 完全一致を継承する。
  - 本番の既定は変えない。どの判定でも本イシューでは定数を変えない。SME 自体が既定 OFF (SME_PRODUCTION_ENABLED = false) なので、
    ADOPT でも本番に効くのは #4156 で SME 既定 ON が ADOPT された場合だけ。
  - 新しい asm!・unsafe・多タイル化は入れない。計算結果の bit は変えない (jpw とプールのスレッド数は job の大きさと並列度を決めるだけ)。

1. 腕 (どれも SME ON が前提。機構は crates/backend-cpu/src/gemm_blis/sme_small_sched.rs。対象帯は SME 適格かつ m,n,k <= 256 = 実質 m=n=256・k 64..256)
  - base    : on-arm.patch だけ (SME ON。機構は OFF)。THREADS=0 (プールは 10 のまま)・JPW=0 (jpw=2 のまま)。0.888 の基準。
  - aa      : base と同一バイナリ。ノイズ幅の記録だけ (判定に使わない)。
  - t4      : base + arm-t4.patch      (THREADS=4, JPW=0)   P コア数・#3175 の T=4 最大。
  - t6      : base + arm-t6.patch      (THREADS=6, JPW=0)   中間。
  - jpw1    : base + arm-jpw1.patch    (THREADS=0, JPW=1)   分配の粗化。
  - jpw4    : base + arm-jpw4.patch    (THREADS=0, JPW=4)   分配の細分化。
  - t4-jpw1 : base + arm-t4-jpw1.patch (THREADS=4, JPW=1)   組み合わせ。
  - 比 = 腕 / base (round ごと)。1.00 以下なら腕が速い。aggregate.py の ARMS・CANDIDATES と一致させる。
  - 腕は結果を見てから足さない。足すなら RULE-reopen を末尾へ追記して新しい WORK で測る。

2. セル (数値を見る前に固定)
  - 判定セル (到達): bench-fandhe の gemm 256 fresh と reuse (device=cpu)。
  - ガードセル: gemm 512 fresh/reuse、train size=64 fresh/reuse。対象帯の外のため、機構が効かないこと (後退がないこと) の確認に使う。
  - gemm 1024/2048 は測らない。対象帯の外であることは P-FIRE の構造検査 (512^3 と (784,256,64) の発火数 0) で確かめる。
  - reuse は #3635 以降の常駐入力経路。#3232 の値とは条件が違うので旧値と並べて比べない。

3. ラウンド数・実行順
  - 5 round 固定。round ごとに 7 腕の起動順をローテーションする。

4. 前提ゲート (1 つでも不成立なら undetermined。FAIL は常に先)
  - P-TREE   : 各腕ツリーと base で内容が違うファイルが期待どおり (mod.rs の 1 行と sme_small_sched.rs の定数行) だけ。patch の sha256 一致・git apply --check・
               未追跡のビルド入力なし。cargo tree -p bench-fandhe で fandhe-ai が path patch の facade に解決する。
               BASE と tree_sha の間で crates/・scripts/bench/・Cargo.toml・Cargo.lock・rust-toolchain.toml に差分なし。
  - P-R0     : 全ツリーで sme_report().kernel_enabled == true。
  - P-FIRE   : 各ツリーで #[ignore] の lib テスト report_sme_small_sched_probe を --exact で 1 件。256^3 の発火数が候補の腕で 1 以上・base/aa で 0。512^3 と (784,256,64) は全腕で 0。
  - P-RT     : base/aa は cargo test -p fandhe-ai-backend-cpu --release -- --skip sme_production_disabled_after_gb10_reject が全件 pass。
               候補の腕はさらに --skip sme_small_sched_disabled_by_default も付ける (定数を反転したツリーでは作りの上で落ちるドリフト検出。名前は計測前に固定)。
               落ちたテストは直さず名前を記録し「後退あり相当 (要調査)」とする。
  - P-BIT    : 各腕ツリーで #[ignore] テスト sme_small_sched_bit_exact_vs_default_when_sme_available (256^3 の出力の to_bits が単一連続 K ループの FMA 参照と全一致)。
               不一致は FAIL。SKIP (SME 非搭載) は undetermined。
  - checksum : 全セルで全腕の checksum が完全一致。不一致は FAIL。
  - P-CELLS  : 6 セル x 7 腕 x 5 行ちょうど。重複・欠損・非有限値は不成立。
  - P-LOCK   : 実機ロック (~/work/.fandhe-hw-lock) を保持し、取得・解放時刻を hwlock.log に残した。
  - P-GATE   : 5/5 round が load1 < 3.0 (30 秒間隔・最大 30 分待ち)。
  - P-COLLECT: 収録前のマスク漏れ検査 (ホスト名・/Users/・/home/・ユーザー名・IP) が 0 件。
  - RAYON_NUM_THREADS が設定されていれば実行を拒否する (専用プールが env_override で無効化されるため)。計測中はビルドを並走させない。全腕のビルドは計測の前に逐次で済ませる。
  - GB10 は対象外: SME 非搭載で sme_kernel_for_shape が常に None になり機構に到達しない。単体テストで構造的に担保する。GB10-MODE の決定は不要。

5. 判定 (評価順 FAIL > undetermined (前提ゲート不成立) > ADOPT(X) > REJECT > undetermined。緩めない)
  - 候補 X が ADOPT 適格 (すべて満たす):
      (a) 判定 2 セルとも、5 round 中央値 <= 1.00 かつ 5/5 round で <= 1.00
      (b) ガード 4 セルのどれにも、5/5 round すべてで > 1.00 の一貫した後退がない
      (c) checksum 完全一致、P-BIT 一致
  - 選択: 適格な候補のうち、判定 2 セルの中央値比の幾何平均が最小のもの。差が 0.005 未満なら変更パラメータの少ないものを選ぶ。それでも並ぶなら jpw だけの腕 (新しいスレッドを立てない) を優先する。
  - REJECT = 全候補で「判定セルの 5/5 後退またはガードの 5/5 後退」。適格な候補がなく、全候補が後退でもない場合は undetermined。
  - 候補が 5 つあるため多重比較になる。限界として記録する (緩和・補正はしない)。

6. 記録だけ (判定には使わない)
  - A/A の腕の比の幅。
  - PyTorch 比 (bench_py.py。torch median_s / fandhe median_s。gemm 256・512 fresh) を base と選んだ腕の両方。
  - NB-RANGE5・NB-SEP。#4142 (docs/perf/noise-band-decision.md) は所有者承認待ちで承認欄は未取得。承認済みとは書かない。定義が変われば RULE.v2.txt で改訂する。

7. 処置
  - ADOPT / REJECT / FAIL / undetermined のどれでも、本イシューでは定数を変えない。
  - ADOPT なら Phase 4 (#4165) の入力として記録する。その際 #4156 が ADOPT であることと SME の unsafe 独立監査 (#4157) を前提として併記する。
  - 再計測するときは末尾に RULE-reopen を追記してから新しい WORK で測る。既存の系列は差し替えない。

8. マスク規則
  - 収録するログのホスト名は <metal-node>、$HOME は <home>、ユーザー名・絶対パス・IP は除去する。実機のホスト名・接続情報はリポに書かない。
  - rev-stamp と tree_fingerprint を成果物に含める。

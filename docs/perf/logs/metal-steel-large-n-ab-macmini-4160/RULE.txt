3. 形状と腕
   正方 NN の N ∈ {256, 512, 1024, 2048, 4096}。入力は決定的シードの有限値。
   - cur: MetalGemm::new（現行 #3206 の M4Base 表）。判定の基準。
   - sl : MetalGemm::new_with_steel_large_n(ctx, true)。判定の対象。
   - ref: new_with_steel_candidate(ctx, true, true, true) で CANDIDATES[0] を強制。bit 一致の照合専用（時間は記録のみ）。
   - cur_aa: cur と同構成の 2 本目。A/A 対照（記録のみ。判定に使わない）。
   スコープは (1024,1024,1024)・(2048,2048,2048)・(4096,4096,4096) の 3 点との完全一致。M4Base 以外・N<=512・非正方・
   8192 以上は対象外（既存の表選択のまま）。

4. 到達追跡（決定的・閾値なし。5 run の全一致を整合検査とし、不一致は fail-closed）
   - N>=1024 の sl が profile=steel_large_n・cfg=CANDIDATES[0]・route=Classic・fallback=false。
   - N<=512 の sl が profile=table で cur と同一タイル・fallback=false。
   成立しない N は「前提不成立」として undetermined（推定で埋めない）。

5. 前提ゲート（性能 run の前に 1 回。1 件でも落ちたら系列を開始しない）
   tile:: 単体テスト、既存 gemm_steel_candidate_diag_tests 全件、steel_large_n_bit_identity、steel_large_n_prereq_parity
   （matmul_reference_fma を参照とした REQ-2 統一複合判定。tolerance は不変）。不一致の N は NOT_ADOPTABLE。

6. 回数と負荷
   5 プロセス（5 run）。値は run 内中央値（warmup 20 + 計測 20、trial ごとに腕の順序を巡回）の 5 run 中央値とし、
   run 別の値も表に出す。各プロセスの前に hw-lock と load1 < 3.0 を 30 秒間隔・最大 30 分待つ
   （GATE-TIMEOUT／GATE-INVALID を記録）。全プロセスが通過した系列だけを正式系列とする。
   ビルド・集計・転送はゲート付き区間の外で行う。
   他ジョブの前提ゲート（docs/perf/logs/macmini-foreign-job-gate/foreign_job_gate.py。基準 G1〜G4 は同 README。load1 の閾値・
   分類式・確度の規則は変えず、厳しくする方向だけの追加）: 各プロセス（純カーネル計測の trace・kern・candle、セル A/B の
   round 先頭と各セルの実行）の前は「他ジョブ CLEAN かつ load1 < 3.0」を 30 秒間隔・最大 60 回（30 分）同じループで待ち、
   後に 1 回確かめる。開始前に揃わなければ GATE-TIMEOUT（reason=foreign-job|load1）、ゲート自身の失敗・出力の解釈失敗は
   GATE-INVALID（reason=foreign-gate-error）、終了後に FOREIGN なら GATE-INVALID（reason=foreign-after）を同じ label の行として
   記録する。いずれも既存と同じく記録して続行し、そうした行を含む系列は正式系列にしない（部分系列は作らない・差し替えない）。
   FOREIGN_GATE（ゲートの絶対パス）は必須で、未指定なら起動しない。各回のゲート出力は出力ディレクトリの foreign-gate/ 以下。
   ゲートのスクリプトと ab_foreign_gate.sh の sha256 は RULE.txt 固定時に併記する（固定時点のものを使う）。

7. 純カーネルの判定（N=1024／2048／4096。指標は kernel_gpu）
   - ADOPT_CANDIDATE: sl/cur の 5 run 中央値で 2% を超えて速い、かつ 5/5 run で速い、かつ parity pass・ref との bit 一致・
     fallback なし・到達が成立。
   - REJECT_CELL: 上記以外。2% を超えて遅く、かつ 5/5 run で遅いものは「後退」として区別して記録する。
   - NOT_ADOPTABLE: bit 不一致・parity fail・fallback。
   - undetermined: 正式系列でない・欠損・非有限値・到達の前提不成立。

8. N=256／512 の no-op
   ON と OFF で解決タイルが同じで、出力が bit 一致することを assert する。崩れたら性能の所見ではなく**欠陥**として系列を無効にする。

9. gemm Metal セルの A/B（非後退ゲート。改善の根拠にしない）
   - before は main の facade、after は定数 1 行だけを true にした checkout。いずれも [patch.crates-io.fandhe-ai] の path patch でビルド。
     before と after のバイナリ sha256 が同じなら fail-closed で停止する。
   - セルは metal × gemm × N {256,512,1024,2048,4096} × {fresh, reuse}。5 round で、round ごとに起動順を反転する。
   - 比較は compare_gemm_ab.py --sizes metal-square5 --threshold 1.00 --per-run --require-checksum-exact。checksum 不一致は FAIL。
   - 同じ round で bench-candle --task gemm --device metal も測る（record_only）。

10. スコアボード比と「1 位」の判定（M-MTL-G1024・M-MTL-G2048 だけ。G4096 は記録のみ）
   - round 別の比 = candle の gemm 窓（fresh）÷ fandhe-ai の reuse 窓（同じ round）。
   - ノイズ帯 = NB-RANGE5（各腕の round 別比の最小〜最大。腕ごとに算出する）。
   - 「1 位に変わった」と書けるのは NB-SEP が成立したときだけ: after の 5/5 round で比 > 1.0、かつ after の最小 > before の最大
     （before は同じセッションで測る）。成立しなければ「改善傾向・確定せず」または「変化なし／後退」と書く。
   - 相手は candle だけを測る。スコアボードの他の相手は対象外。
   - NB-RANGE5／NB-SEP は docs/perf/noise-band-decision.md（#4142）の定義を名前で参照する。同 doc は #4142 で所有者承認済み
     （2026-11-10。https://github.com/Fandhe-AI/fandhe-ai/issues/4142#issuecomment-6757497844 ）。
     定義や名前が変わったら RULE.v2.txt で改訂する。

11. 総合判定
   - UNDETERMINED: 必要なセルが 1 件でも undetermined なら最優先。
   - ADOPT: 1024／2048 の少なくとも 1 つが ADOPT_CANDIDATE、スコープ内に NOT_ADOPTABLE と「後退」がなく、N<=512 の no-op が成立し、
     セル A/B で 5/5 round 一貫して 2% を超えて後退するセルがない。
   - REJECT: 上記以外。
   - スコープ（3 点）を事後に絞って ADOPT を作ることは禁止する。判定は Mac mini 単機のもの（M4 Max での確認は結線前に別途必要）。

12. 運用
   - run の差し替え・追加・除外・上書きは禁止。再実行は別ラベルで行い、旧系列も残す。
   - nohup で切り離して起動し、生存を確認する。2 時間を超えるならセッションを分ける。
   - 純カーネルの計測とセル A/B を同時に走らせない。
   - aggregate.py は固定時点のものを使う（aggregate_script_sha256 で照合）。

## run 単位の符号一貫性（有効性判断の根拠）

- **L0-P0**: N=1024 は 5/5 run で base より速い（ratio<1.0 が一貫）。N=2048 は
  3/5 run で速い・2/5 run で遅い（符号不一致・ratio は base 比 ±0.5% 以内で
  ノイズ域）。N=4096 は 3/5 run で速い・2/5 run で遅い（run1・run4 は base 側も
  同時に高い値を示す高負荷回による外れ値。符号不一致）。→ **N=1024 の改善方向は
  一貫するが N=2048/4096 で符号が反転し不安定**
- **L0-P8**: N=2048 は 5/5 run で base より速い（一貫。ただし差は 1.2〜1.9%）。
  N=4096 は 3/5 run で速い・2/5 run で遅い（符号不一致）。N=1024 は概ね base と
  同等（±1%）。
- **L1-P0／L1-P4／L1-P8**（`RowStrided` レイアウト）: **N=4096 は 5/5 run すべてで
  base より遅い**（符号完全一致。ratio 中央値 1.058〜1.154）。N=1024/2048 は
  base と概ね同等（±2%）。

## 判定材料の要約

- N=4096 で `RowStrided`（L1 系）が符号一貫かつ 5.6〜15.4% の明確な後退を示す
  一方、`RowLinear`（L0 系）は改善方向の候補（L0-P0）はあるが符号が run 間で
  反転し（N=2048/4096）、環境ノイズ（`uptime_before_run*.txt`・`pmset_therm_*`
  参照。全 5 run とも共有負荷下）の範囲内で説明可能な水準（1〜3%）に留まる
- 詳細な採否判断は `docs/perf/metal-gemm-n4096-kernel-gap.md` §11.4 を参照

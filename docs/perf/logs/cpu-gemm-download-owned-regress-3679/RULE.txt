系列と run:
- 機体ごとに 3 系列。各系列は別セッションとして起動し、hw-lock を取り直し、別ラベル（s1 から）を付ける。
- 1 系列は 5 run。各 run で before と after を別プロセスで起動し、run ごとに順を反転する（ABBA）。
- 系列の先頭腕は交互にする（s1 は before 先・s2 は after 先・s3 は before 先・s4 は after 先・s5 は before 先）。
- 診断の反復数は cpu_gemm_resident_reuse_diag.rs の iters_for 既定のまま。縮めない。

ゲートと打ち切り:
- GB10: 系列の前・途中（30 秒間隔の poller）・後で compute プロセスが 0 件（excl_check.py --series main が pass）
  かつ各 run の前に load1 < 1.0。Mac mini: 各 run の前に load1 < 3.0。
- ゲートを通らない run を含む系列は record_only とし、判定に使わない。

  選ぶ基準はゲートだけで、値を見て選ばない。run の差し替え・追加・セルの除外はしない。

指標: ratio_r = after_r / before_r（同じ系列・同じ run 番号の対。phase=iter_total の median_s）。
      セルごとに 3 系列 x 5 run = 15 個を使う。

判定（セルごと。互いに排他で、すべての場合を覆う。上から順に適用する）:
- k = 15 個のうち ratio_r > 1.00 の個数（1.00 ちょうどは数えない）。
1. 判定不能（系列不足）: ゲートを pass した系列が 3 未満。
2. 判定不能（checksum）: 当該 (腕, N) の checksum_bits が before・after の全 run で一致しない。
3. 再現した: k >= 12（片側の符号検定で p ≈ 0.018）かつ、3 系列それぞれの中央値 ratio > 1.00。
4. 再現しない: k <= 7（15 個の中央値が 1.00 以下であることと同じ）。
5. 判定不能: 上のどれにも当たらない（8 <= k <= 11、または k >= 12 で中央値が 1.00 以下の系列がある）。
- 記録のみ: 15 個の中央値 ratio、系列ごとの中央値と「5/5 run で > 1.00 か」、ノイズ参考として
  系列ごとに T1〜T3 以外の診断セルが 5/5 > 1.00・5/5 < 1.00 になった件数。
- 帰無仮説（差なし）で 1 セルが 5/5 後退する確率は 1/32 で、約 90 セルでは約 2.8 件が偶然当たる。

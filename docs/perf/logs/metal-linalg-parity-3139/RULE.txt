理由:
  上記「対象コミット」d7d8d503 以降に crates/ 配下が更新されており、元の「crates/ 配下が同一」条件は満たせない。
  #2676 の RULE（docs/perf/logs/metal-linalg-lu-chol-qr-2676/RULE.txt）が、線形代数関連ファイルの差分は
  κ ガード（判定が厳しくなる方向・デバイス非接触）以外 0 件であることを確認済みで、それ以降
  linalg.metal・linalg_kernel.rs・linalg.rs・linalg_model.rs・tests/linalg_parity*.rs・backend-cpu/src/linalg.rs は
  変更がない。今回の差分は記録専用の診断テスト 2 件の追加のみ（判定ロジック・入力集合・tolerance 不変）:
    - tests/linalg_parity.rs::qr_diagnose_all_cases_on_device（実機。assert しない）
    - tests/linalg_model_parity.rs::qr_input_model_vs_cpu_diagnostic（デバイス不要。assert しない）
    - tests/linalg_parity_inputs.rs::diag_compare（診断出力の共通ヘルパー）

  2 行目に dirty=0 が必須で、満たさない実測は無効とする。.rev-stamp は転送後にノード上へ直接書く。

  pass の根拠にしない。

判定（元の RULE の判定・入力集合・fail 時の扱いはすべて不変）:

  実機ロックは ~/work/.fandhe-hw-lock を mkdir で取得し、失敗時も必ず解放する。計測中は他のビルドを並走させない。

事前に宣言する仮説（判別の手順の宣言であり、結果を見た後の判定変更ではない）:
  #2676 の 2026-10-27 実測で qr R 3x8 scale=1e20 が fail した（コミット 1184586ee）。登録時点の観察:
  等倍 qr_input(3,8) の R[0,2] は厳密 0（第 0 列と第 2 列が直交）で、f64 参照は約 1e-16 相対の残差、
  f32 は約 1e-7 相対の残差を持つ。1e20 倍では絶対救済（1e-5）が効かず相対誤差だけが判定になり fail する。
  f32 ホストモデル対 CPU の診断（model-diag.log。デバイス不要）が同じ要素 [0,2] で同形の不一致を出し、
  かつ実機の GPU がモデルと一致するなら、精度クラス（f32 対 f64）による不可避の差でありカーネルのずれではない。
  GPU がモデルからずれるなら #3137 側でカーネルの是正が必要。

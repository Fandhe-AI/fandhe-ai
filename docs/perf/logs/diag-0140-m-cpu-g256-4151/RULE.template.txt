4. 計測手順
  ラウンド数は PARAMS の rounds（既定 5）。各ラウンドの前にゲートを通す。
    Mac mini: hw-lock を取得し、load1 < 3.0 を最大 30 分待つ。ビルドはゲートの前に済ませ、計測中に並走させない。
  ゲート不通過は gate.txt に TIMEOUT と記録し、そのラウンドを正式系列から外す（status=partial・確度は常に低・表題は「参考」）。
  腕の順序は奇数ラウンドと偶数ラウンドで入れ替える（run_round.sh）。RAYON_NUM_THREADS は設定しない。
  系列（example）: hot（連続）・gap（各呼び出しの前に gap_us だけスピン待ち。worker が寝た状態からの起床を含める）・
  serial_t1（参照）・forkjoin_floor_hot／gap（fork-join の床。job 数は 2×スレッド数）・cold_first_call（記録のみ。計測窓の外）。
  warmup 50・測定 500。bench-fandhe gemm 256 の fresh と reuse（スコアボードと同じ窓）、PyTorch の bench_py.py gemm 256 fresh と
  torch_cpu_mlp_diag.py の mm_pure を同じラウンドで取る。sme_microcall_fixed_cost_probe は off-base ツリーだけで実行する。
  run の差し替え・追加・除外・上書きは禁止。再実行は別ラベルとし、旧系列を残す。
  到達不能な量は unavailable と記録し、推定値で埋めない（values.tsv にも書かない。式が計測できないなら RULE を改訂して式を外す）。
  保存物: round{i}/{gate.txt, values.tsv, raw/}・env/。values.tsv は quantity／value の 2 列（W_off W_on Wf_off Wf_on O K_opp は ms、
  c_sme_kc0_ns c_sme_intercept_ns は ns）。変換手順は計測する issue が README に残す。

5. 区間の操作的定義（時計はすべて wall。diag_timing.patch が計る）
  pre        gemm_blis_parallel_with_transpose の入口から par_iter_mut の直前まで（grid は入口から job_grid 直後まで、split は grid から split_c_into_jobs 直後まで）
  fork_wake  par_iter_mut の呼び出しから各 worker の最初の job が始まるまで（min・max）
  stage_in／stage_out  c_local の確保と copy-in／copy-out（job 合計）
  alloc      PanelBuffers::new（job 合計）
  pack_b／pack_a  B pack ループ／A pack ループ（job 合計）
  kernel     jr／ir ループ全体（端タイルのコピーを含む。job 合計）
  join       最後の job が終わってから par_iter_mut が戻るまで
  region_wall par_iter_mut の呼び出しから戻りまで
  導出: kernel_ideal = Σkernel ÷ P_used・kernel_crit = max_worker Σkernel・imbalance = kernel_crit − kernel_ideal・
        F_drv = G − kernel_ideal（G は base 腕の hot 中央値）・perturbation = (timed の G − base の G) ÷ base の G。
  smstart／smstop は新しい asm! なしでは切り出せない。n_calls × c_sme ÷ P_used の上限として別欄に出す（kernel の内側。F_drv には足さない）。

6. 診断式と判定規則（単位 ms。比はラウンド別の値の中央値。判定は OFF 腕で行い、ON 腕は同じ式の値を記録するだけで分類を動かさない）
  W = bench-fandhe gemm 256 の reuse 窓、Wf = 同 fresh 窓、O = PyTorch fresh 窓、K_opp = PyTorch の mm_pure。
  F2     = O ÷ Wf
  F1     = O ÷ (W − G + K_opp)
  F1_drv = O ÷ (W − F_drv)
  分類先: 自分たちの制約／ハードの上限／計測窓の定義／分類保留
  (1) F2 が reach_threshold 以上 → 「計測窓の定義」。
  (2) そうでなく F1 が reach_threshold 以上なら GEMM 呼び出しの中を分ける。
      F1_drv が reach_threshold 以上 → 「ハードの上限」は成り立たない。「自分たちの制約」とし、理由は「GEMM 駆動部の固定費（区間別の数字）」。
        根拠: 完全自作コア（REQ-1）で自前の駆動部を持つことによる固定費であり、閉源ライブラリやハードが決める部分ではない。
      そうでなければ → kernel_owner の宣言どおり（hardware なら「ハードの上限」。閉源 Accelerate 相当のカーネル速度で決まる）。
      この解釈は測る前に宣言し、事後に動かさない。
  (3) それ以外 → 「分類保留」。理由は「GEMM の外の区間が主因。別の診断へ」。
  確度: 高 = 全ラウンド PASS（status=formal）かつ判定に使った式のラウンド別の値がすべて閾値の同じ側（境界ちょうどはまたぐ扱い）かつ
        |perturbation| が perturbation_max 以下。低 = それ以外（理由欄の先頭に「確度低」）。
  ドリフト: 観測比 O ÷ W の中央値が scoreboard_ratio から 10% を超えて乖離したら記録する（判定は変えない）。
  停止条件: 区間の和（job 合計 ÷ P_used）が region_wall を sum_tolerance 超えて超える・d_n_calls が手計算の下限
  （ceil(dim/MR)×ceil(dim/NR)×ceil(dim/kc)）を下回る・d_regions が calls と一致しない。

9. 限界
  plain GEMM の入口で、bias_act 融合経路ではない。kernel は端タイルのコピーを含む。E コアと P コアは分けられない
  （macOS に正式な pinning の手段がない。#3175 §5）。smstart／smstop は上限値。gap_us が実ベンチ窓の直列区間の起床コストを
  再現できているかは未検証。

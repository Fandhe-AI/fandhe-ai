## B 系列（結線判断の主根拠。`kernel_gpu_ab_best_run{1..5}.log`）

抽出:

```sh
grep '^N=<N> pair=hfrag_best_vs_production\|^N=<N> pair=best_vs_production_select' "$LOGDIR"/kernel_gpu_ab_best_run*.log
```

head は S 系列で確定した N 別最良タイル（`HFRAG_BEST_BY_N`）、base は
本番選択構成（f32・`tile::select_for_device`）。

| N | base tile | head tile | base(f32) median (ms) | head(hfrag) median (ms) | 5 run ratio | 符号一貫性 | 判定 |
|---|---|---|---|---|---|---|---|
| 512 | (64,32,32,2,2) | 同左 | 0.0462 | 0.0495 | 1.0753/1.0728/1.0665/1.0740/1.0703 | 5/5 (hfrag遅い) | **REJECT** |
| 1024 | (64,32,8,4,1) | 同左 | 0.2245 | 0.2317 | 1.0455/1.0260/1.0287/0.8941/1.0321 | 不一致（1 run 逆転） | **undetermined** |
| 2048 | (64,32,16,2,2) | (64,64,16,2,2) | 1.6102 | 1.5551 | 0.9573/1.1491/1.0788/0.9629/0.9646 | 不一致（2 run 逆転） | **undetermined** |
| 4096 | (32,64,16,2,2) | (64,64,32,2,2) | 13.6670 | 12.2688 | 0.8970/0.8980/0.8985/0.8980/0.8972 | **5/5 (hfrag速い)** | **ADOPT-as-opt-in-candidate** |

N=512/1024 の head タイルは S 系列対象外のため base（本番選択構成）と
同一タイルであり、A 系列の N=512 と本質的に同じ比較（B の base は
`select_for_device` を毎回呼んで再解決するため run 間の絶対値が bimodal
だが、比自体は A 系列と整合する。両系列とも 5/5 符号一貫で hfrag が
6.7〜7.5% 遅い）。

**N=4096 のみ、hfrag が本番選択構成に対し 5/5 run 符号一貫（比の分散も
0.897〜0.899 と極小）で約 10.2〜11.5% 高速**。この速さは「hfrag タイル
（cand9・`bk=32`）が f32 タイル（cand2・`bk=16`）と異なる」ことに由来し、
A 系列（同一タイル比較）が示すとおり同一タイルでは hfrag は f32 より
遅い。つまり「half MMA 自体の演算スループット向上」ではなく「hfrag の
SMEM 使用量が f32 のちょうど半分（`shared_mem_bytes_hfrag_for`）である
ため、f32 の本番選択では選ばれない bk=32・64×64 構成が hfrag では最速に
なる」という**間接効果だと推測される**（A 系列・B 系列は SMEM 使用量
だけを対照した比較ではないため、この帰属は仮説であり、cand9 高速化を
SMEM 節約のみに帰属させる断定でも half MMA 自体の優位性を否定する
断定でもない点に注意。`CANDIDATES[9]`〈f32・bk=32〉自体は実行可能
〈viable〉であり本番選択構成比 4.5〜7.6 倍遅いという理由で REJECT
されている——SMEM 不足で実行不能という意味の非 viable ではない。
`docs/perf/metal-gemm-hfrag-candidate.md` §9.6・
`docs/perf/metal-gemm-n4096-kernel-gap.md` §14 参照）。

## 妥当性帯チェック（#1275 分母との突合。副次）

`docs/perf/metal-gemm-reuse-phase-breakdown.md` §11.5 の分母（正式な
`gemm_reuse_phase_diag_production_batch` プロトコル。5 プロセス起動・
20 warmup + 20 測定）: N=1024 1.0267 ms・N=2048 3.1849 ms・N=4096
13.7051 ms。

本イシューの A/B 系列 base（f32・同一プロトコル・同一
`measure_one_phase_trial_with` 経路）: N=1024 約 0.22〜1.02 ms
（bimodal）・N=2048 約 1.61 ms・N=4096 約 13.67〜13.74 ms。

N=4096 は分母と概ね整合（13.67〜13.74 対 13.7051 ms）。N=1024/2048 は
既知のプロトコル間乖離（`docs/perf/metal-gemm-n4096-kernel-gap.md`
§16.4 が記録する run 間変動・機種共有負荷の影響）の範囲内と考えられ、
本イシューの判定はこの妥当性帯チェックを単独の判定根拠にしない
（同一 run・同一プロトコル内の `head_over_base_kernel_gpu` を主判定と
する。ファイル冒頭記載の設計方針）。

## 他セッション負荷変動（記録）

実行時 `uptime` は load average 約 6〜8・20 ユーザー共有環境
（`uptime_before_*_run*.txt` 参照）。N=512/1024 の一部 cfg で 5 run 間に
最大 約 4.5 倍の二峰性（同一構成・同一 N でも run によって束が変わる）
が観測された。これは本ハーネスの契約検証（`resolved_cfg == cfg`・
複合判定 pass）はすべて成立したうえでの計測ノイズであり、`docs/perf/
metal-gemm-transpose-tiled.md`「#1186/#1187」等で記録済みの同種の
共有負荷影響と整合する。N=1024/2048 の「符号不一致」判定はこの影響を
反映したものであり、機構上の欠陥ではない。

[増強の内容]
- 非 capture スレッドのずれた loss を、reference.losses の全 200 件と replay スレッドの実 loss 列の両方へ照合する（DIAG3610 行。DIAG3596 行も従来どおり出す）。
- replay スレッドは step ごとに完了数を共有カウンタへ書く。非 capture 側は step の直前と loss 読み出し直後に読み、`replay-window [before, after]` として出す。
- 20 step の参照パラメータ（run_scenario(20, …)）を作り、非 capture の各 repeat の loss ループの後で param_bits を比べる（`plain-params-equal=`）。
- 失敗時は replay の 200 件・参照の 200 件・ずれた repeat の loss 列（bit 値）を `DIAG3610 series` 行で全件出す。
- run ごとに要約 1 行: `DIAG3610 summary: mismatches= matched_full= unmatched= idx_ge_20= in_window= plain_params_diff= replay_bad=`。
  matched_full = 全 200 件の参照または replay の実 loss 列のどれかと bit 一致したずれの数、unmatched = どれとも一致しなかった数、idx_ge_20 = 一致 index に 20 以上を含む数、in_window = 一致 index j が [before, after+1] に入る数（補強の指標。進捗カウンタはホスト側の step 完了数による近似）、plain_params_diff = パラメータがずれた repeat 数。

[事前表明する仮説（推定であり合格ラインではない）]
- H1 探索範囲の不足（見かけ上の食い違い）〔推定〕: ずれた plain の loss は replay スレッドのある step の loss と bit 一致し、その index は 20 以上（short の外）にある。§8.11.6 の機構（finalize が graph の partial を読む）と矛盾しない。
  支持: ずれた値がすべて 200 件の参照または replay の実 loss 列のいずれかと bit 一致する（unmatched = 0 かつ matched_full = mismatches）。補強: in_window が mismatches に近い。
  棄却: 一致しない値が 1 件でもある。
- H2 部分和の混在・部分的な上書き〔推定〕: finalize が読む partial に graph の分と自分の分が混じる。
  支持: ずれた値が、200 件の参照・replay の実 loss 列のどれとも一致しない（unmatched >= 1）。
  棄却: すべて一致する。
- H3 loss 以外の汚染〔推定〕: 非 capture のパラメータも参照からずれる。
  支持: plain_params_diff >= 1。棄却: 全 repeat で一致する。
- H4 不再現: before 側（f7fe6b4df・c1204755e）の各 5 回に、mismatches >= 1 の run が 1 つもない。判定不能として記録し、追加の起動はしない。
- 対照: after に同じ増強を当てる。mismatches や plain_params_diff が 1 件でも出れば、修正が不十分な可能性として所有者へ報告する（その場では直さない）。

[分類規則（計測前に固定。事後に変えない）]
各ツリーの全 run の要約行を集計して当てはめる。複数に当てはまる場合は併記する。要約行や run が欠けたら、その分は「欠損」として別記し、当てはまる場合に数えない。
- (a) before と main_prefix のいずれかで mismatches >= 1 の run があり、全 run を通して unmatched = 0、plain_params_diff = 0、after は 5/5 で mismatches = 0 かつ plain_params_diff = 0 → §8.11.6 の機構の推定は実測と整合する。食い違いは診断の照合範囲（先頭 20 件）によるものと記録する。
- (b) 全 run を通して unmatched >= 1 → 機構は未確定。残る仮説と必要な追加診断（partial の中身の記録など）を記録する。
- (c) plain_params_diff >= 1 の run がある → loss だけの取り違えという記述を改める。修正範囲の見直しは所有者判断事項にする（その場では直さない）。
- (d) before と main_prefix の全 10 run で mismatches = 0 → 判定不能（不再現）。仮説は残したまま記録する。
- (e) after の run に mismatches >= 1 または plain_params_diff >= 1 がある → 修正が不十分な可能性。所有者判断事項にする（その場では直さない）。

[限界]

[hard 条件（判定より先）]
- 4 腕の checksum（最終 loss）が全 run で完全一致。PARAM_DIGEST も全 run・全腕で同値（欠落は不一致として扱う）。
- 不一致は REGRESSION（正しさの失敗）。

[比]
- graph モード m ∈ {off, on} ごとに ratio_m = median(excl1-m の 5 run の median_s) / median(excl0-m の 5 run の median_s)。ratio_r = 同一 round 内の excl1-m / excl0-m。
- 基準値 1.00 は #2115・#3261 の「全セル ≤ 1.00」の前例に揃える。

[判定]
- NON-REGRESSION（すべて満たす）: 専有ゲート全 round 通過／前提ゲート g1〜g4 合格／hard 条件／両モードで ratio <= 1.00。
- REGRESSION（いずれか）: いずれかのモードで ratio > 1.00 かつ 5/5 round で ratio_r > 1.00／hard 条件の不一致／前提ゲート g1〜g4 の失敗。
- UNDETERMINED（いずれか）: 専有ゲート不通過／run 数不足・欠測／前提ゲートのログ欠落・未実行／GB10 以外／env_info・RULE sha・パッチ sha・before SHA・crates 同一性の不一致／ratio > 1.00 だが 5/5 の符号一貫がない。
- 判定の優先順: 入力不正 → undetermined 要因 → 正しさの失敗 → 比。
- 後退や判定不能になっても、コード・tolerance・閾値は変えない。結果を記録し、所有者判断事項として報告する。

[事前表明する仮説（推定・合格ラインではない）]
- 既定 OFF（legacy stream）: is_capturable_stream() == false でトークンをすぐ手放すため、追加費用は mutex と atomic 程度。中立（0.98〜1.02）と見込む。
- opt-in ON: replay される step はスコープを取らず、影響は warm-up と capture の step に限られる。中立と見込む。
- 修正（r2）: 1 スレッドでは replay・初回 launch ごとに、競合のない MSE ワークスペース mutex を 1 回取るだけ。中立と見込む。

[限界]

- 単一機体（GB10）・train CUDA・size=64 の結果であり他の構成に及ばない。
- 並行時（2 スレッド）の性能は対象外。受入基準は 1 スレッドの非後退のみ。
- 2 つの別ビルドの比較であり、バイナリの差は排他以外（#3597 と同時期の変更）を含みうる。crates/ 同一性検査は after 側だけを固定する。

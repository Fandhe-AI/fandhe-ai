3. 前提ゲート (1 つでも不成立なら undetermined。理由はすべて併記)
  - P-TREE   : 両ツリーで内容が異なるファイルが gemm_blis/mod.rs の 1 件だけ (ファイル一覧の一致と cmp)、
               OFF の該当行が `const SME_PRODUCTION_ENABLED: bool = false;`、ON が true、patch の sha256 が上記と一致。
  - P-R0     : 両腕で sme_report() の kernel_enabled を記録 (定数には依らず CPU 検出で決まる)。期待値は macmini = 両腕 true、gb10 = 両腕 false。外れたら計測を中止して記録だけ残す。
  - P-RUNAB / P-COLLECT: A/B スクリプトと収録が exit 0。
  - P-CELLS  : 12 セル x 両腕 x 5 行ちょうど (重複・欠損・非有限値は不成立)。
  - P-LOCK   : 実機ロック (~/work/.fandhe-hw-lock) を保持したまま計測し、取得・解放の時刻を hwlock.log に残した。
  - P-GATE   : macmini は 5/5 round が load1 < 3.0 を通過 (gate_ok=1)。gb10 は内側 8.0 の 5/5 round 通過と、外側ゲート (load1 < 1.0 かつ GPU 使用率 0%、最大 20 回待ち) の記録。
  - P-RT     : gb10 のみ。ON ツリーで cargo test -p fandhe-ai-backend-cpu --release (#[ignore] 除く) が全件 pass。落ちたテストは直さず名前を記録し「後退あり相当 (要調査)」とする。
               OFF ツリーでは --lib を実行しない (sme_production_enabled_is_true_with_neon_fallback が作りの上で必ず落ちるため。最初から除外とする)。
  - RAYON_NUM_THREADS が設定されていれば実行を拒否する。

4. 判定 (評価順 FAIL > REJECT > ADOPT > undetermined。緩めない)
  - FAIL: checksum が数値として完全一致しない (どちらかの機の任意セル)。性能判定へ進まず停止し、ON を戻す側に倒す (bit 同一のフォールバックが成り立たないため)。
  - REJECT: どちらかの機のどれかのセルに、全 5 round で after/before > 1.00 の一貫した後退がある。
  - GB10「非後退: pass」: P-R0・P-RT・P-CELLS・P-LOCK・P-GATE が成立し、5/5 一貫の後退セルが無く、checksum が全一致。
    中央値が 1.00 を超えても 5/5 一貫でないセルは「後退の証拠なし (ノイズ帯)」として値と一緒に記録する。
  - ADOPT (Mac mini): 前提ゲートがすべて成立し、到達 10 セルがすべて「5 round 中央値 <= 1.00 かつ 5/5 round <= 1.00」、
    非到達セルに 5/5 一貫の後退が無く、checksum が全一致し、かつ GB10 が「非後退: pass」。
  - 上のどれでもない場合は undetermined。
  - 評価の補足: FAIL（checksum 不一致）は常に最優先。前提ゲート（§3）が 1 つでも不成立なら REJECT より先に undetermined とする
    （ゲート不成立の計測は判定に使わない）。ADOPT は Mac mini の条件に加え GB10 が「非後退: pass」であることを要する（aggregate.py が機械的に結合する）。

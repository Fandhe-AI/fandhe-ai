RULE fixed-at-utc: 2026-10-20T00:00:00Z (実機計測より前にコミットして固定。事後に緩めない)
issue: #3187 GB10 の CPU GEMM で reuse が fresh より遅い原因の帰属
doc: docs/perf/cpu-gemm-reuse-fresh-inversion.md

[実行方法]
- 1 run = 1 プロセス。テストバイナリ
  crates/facade/tests/cpu_gemm_reuse_fresh_diag.rs を
  `--ignored --exact cpu_gemm_reuse_fresh_phases --nocapture --test-threads=1`
  で起動し、出力は 1 つの run{N}.jsonl。
- run1〜run5 の 5 run。差し替え・追加起動・セル除外・既存 run ファイルの上書きはしない。
- 各 (arm, n) のブロックは warmup 20 反復 + 計測 20 反復。これを 4 ラウンド回し、
  ラウンドごとに arm 順を反転する。1 プロセスあたり腕ごとに計測 80 サンプル。
- N = 256・512・1024・2048。対象ホスト: DGX Spark GB10 (gb10) が正式系列、
  Apple M4 Max (m4max) は疎通確認のみ（record_only・判定対象外）。

[腕と区間]
- fresh: tape_build / var_upload / matmul / host_copy / checksum / iter_total（+ 窓外の tape_drop）
- reuse: matmul / host_copy / checksum / iter_total（葉 Var と Tape はブロック内で使い回し）
- fresh_hold: fresh と同じだが Tape をブロック終了まで保持する（結果蓄積の因果腕。tape_drop なし）
- fresh_arena / reuse_arena: fresh / reuse を host arena (#2104) ON で実行
- backend_drop / backend_hold: BackendOps::gemm を直接呼び、結果を捨てる / 保持する（kernel_call）
- fresh_legacy / reuse_legacy: readout を to_tensor().contiguous().as_slice().to_vec() にした補助腕
- Var::matmul は eager で matmul 区間にカーネル時間が入る。host_copy は借用ビュー取得
  （legacy 腕のみ実コピー）。

[代表値]
- 各 (arm, n, phase) は run ごとの median_s を採り、5 run 間の中央値と min-max を報告する。

[checksum 規則（hard・fail-closed）]
- n ごとに全腕・全 run の iter_total.checksum_bits が一致すること（f64 の bit 単位。
  数値として等しいことでは代用しない）。1 件でも不一致なら系列は無効（集計は exit != 0）。
- 0.11.0 境界（boundary）との一致は記録のみで要件にしない。

[再現判定]
- ratio = reuse.iter_total / fresh.iter_total（5 run 中央値同士）。
- ratio > 1.00 なら「逆転が再現」、<= 1.00 なら「非再現」としてその N の帰属は行わない。

[帰属規則（逆転が再現した N ごと）]
- D_matmul   = reuse.matmul    - fresh.matmul
  D_readout  = reuse.host_copy - fresh.host_copy
  D_checksum = reuse.checksum  - fresh.checksum
  G = D_matmul + D_readout + D_checksum
  （fresh だけが払う F_only = fresh.tape_build + fresh.var_upload と、残差
   iter_total - sum(区間) も記録する）
- 1 つの区間差が G の 50% 以上ならその仮説を「支持」。
  matmul -> 出力確保（結果蓄積・ページ確保）、host_copy -> readout 方式、
  checksum -> 読み出し側。どれも 50% に届かなければ「未確定」。
  G <= 0 なら「共有区間では説明できない（未確定）」。
- 因果の確認（結果蓄積）:
  rho_FH = (fresh_hold.matmul - fresh.matmul) / D_matmul >= 0.5
    -> 「出力を保持すること（結果蓄積）が原因」を支持。
  rho_B  = (backend_hold.kernel_call - backend_drop.kernel_call) / D_matmul >= 0.5
    -> 「tape / autodiff ではなく出力バッファの確保パターンが原因」を支持。
  D_matmul <= 0 または未達なら未確定。
- arena A/B（副次）: 前提として fresh_arena の arena hit > 0 であること（不成立なら
  arena 検証は undetermined）。reuse_arena は hit = 0 を予測として事前登録する。
  |reuse_arena.iter_total - reuse.iter_total| < 0.5 * (reuse.iter_total - fresh.iter_total)
  なら「既存の host arena (#2104) では reuse の逆転を是正できない」と記録する。
  fresh_arena と fresh の比較は記録のみ。
- ページ確保の機構（補助・判定外）: GEMM_REUSE_MINFLT=1 を付けた別ディレクトリ（--out）の
  1 run で腕・区間ごとの minflt / iter を記録し、N^2*4/PAGESIZE と並べて報告するのみ。
  5 run の系列では OFF（minflt_delta_per_iter=null）。
- legacy readout 腕・順序効果（q1/q3/min/max）は記録のみ。

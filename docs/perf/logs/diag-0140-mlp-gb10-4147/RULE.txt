4. 診断式（docs/perf/loss-attribution-matrix.md §10.1 から転記。単位は ms）
  入力量: fandhe_window・fandhe_fresh_window・opp_window・fandhe_pure_kernel・opp_pure_kernel
  F1 = opp_window ÷ (fandhe_window − fandhe_pure_kernel + opp_pure_kernel)
       純カーネルの時計タグ（clock 列）を両側で揃える。揃わなければ F1 は比較不能とし、境界を併記する。
       時計が揃っていても純カーネルが窓を上回るラウンド（fandhe 側・opp 側のどちらでも）があれば、
       止めずにそのラウンドの F1 を計算せず「窓超過」と印を付け、そのセルの F1 は比較不能とする（時計不一致と同じ扱い。
       単発 GEMM の和は step 内の状態と一致しないため揺れで超過しうる）。分母 0 以下の検査は変えない。
  F2 = opp_window ÷ fandhe_fresh_window
  観測比 = opp_window ÷ fandhe_window（スコアボードの比との整合確認用）
  1 以上は「相手の構成を再現すれば届く」を意味する。診断であり目標値ではない。
  純カーネルの境界（#4147 で追記。README の「注意」と同じ）: GEMM のみ。ReLU・MSE・SGD・readout・bias は両側とも含まない。
    学習は l1_fwd・l2_fwd・l2_dw・l2_dx・l1_dw の 5 形状（l1_dx は含めない。fandhe-ai の常駐チェーンも PyTorch〈入力に勾配を求めない〉も実行しないため）。推論は l1_fwd・l2_fwd。
    CPU 2 セルの時計タグは両側 wall（fandhe-ai は cpu_jobgrid_bench の median_secs、PyTorch は opp_kernel_torch_diag の mm_pure。単発 GEMM を温めた状態で測った値の和で、step 内の状態とは一致しない）。
    G-CUDA-INF の時計タグは両側 cuda_event（event 対で 1 launch を挟む。H2D・出力確保・event 生成は区間外）。fandhe-ai は cuda_mlp_event_bench_4147（CudaGemm::launch_tiled_f32＝本番と同じ select_tiled_f32_kernel の選択。epilogue 融合は含まない）、PyTorch は opp_kernel_cuda_mlp_diag_4147.py（cuBLAS）。
    fandhe_window は reuse（scoreboard の窓。train は常駐チェーンで第 1 層の dX を計算しない）、fandhe_fresh_window は fresh（train は L1 の dX を計算する）。
    kernel_owner=hardware の根拠（README の「注意」の宣言を転記）: 相手の GEMM は閉源ベンダーライブラリ（CPU は NVPL、CUDA は cuBLAS）で、REQ-1 により fandhe-ai は使わない。
    測る前の宣言で、事後に動かさない。docs/perf/logs/cpu-gemm-resident-reuse-3646/ は G-CPU-INF を「自分たちの制約（条件つき）」と記録しており
    ラベルが食い違うが、kernel_owner は F1 が閾値以上のときの表示ラベルだけを決め、F1・F2 の値は常に記録されるため、所有者が読み替えても再計測は不要。

5. 判定の分類先と規則（優先順位つき。aggregate_diag.py の classify と同一）
  分類先: 自分たちの制約／ハードの上限／計測窓の定義／分類保留
  (1) formulas に F2 があり、F2 の run 間中央値が reach_threshold 以上なら「計測窓の定義」。
  (2) そうでなく F1 があり、時計が揃い窓超過がなく、F1 の run 間中央値が reach_threshold 以上なら、
      kernel_owner=hardware は「ハードの上限」、kernel_owner=constraint は「自分たちの制約」。
      kernel_owner は測る前に宣言する（hardware: 閉源ライブラリ・OS・ハードが決める。
      constraint: REQ-1・REQ-8・既定精度が決める。matrix §10.5 の定義）。事後に動かさない。
  (3) それ以外は「分類保留」。理由欄に「どれも届かない（残差は固定費など別区間。別診断へ）」「F1 の時計不一致」「F1 の窓超過（純カーネル > 窓。round N fandhe／opp）」のいずれかを書く（F1 が比較不能で (1) も当てはまらないとき）。
  確度:
    高: 全ラウンドがゲート PASS（status=formal）かつ、判定に使った式の run 別値がすべて閾値の同じ側
        （最小 > 閾値、または最大 < 閾値。境界ちょうどはまたぐ扱い）かつ時計が揃っていて窓超過がない。
    低: 上記以外。理由欄の先頭に「確度低」を付ける。
  ドリフト: 観測比の中央値が PARAMS の scoreboard_ratio から 10% を超えて乖離したら記録する（判定は変えない）。

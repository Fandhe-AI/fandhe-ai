判定（tolerance 定数 RELATIVE_TOLERANCE／ABSOLUTE_RESCUE_THRESHOLD・baseline・入力・テストコードは不変）:
  共通の pass: exit 0 かつ "running 1 test" かつ "test result: ok. 1 passed; 0 failed"。
  共通の fail: 1 件以上のテスト失敗（パニックを含む）。CUDA と CPU は自前バックエンド同士の比較なので
    判定不能にせず通常の失敗として扱う。
  undetermined: timeout（exit 124）、--list で選ばれた件数が 1 でない、ビルド不能、ノード到達不能。
  テストごとの判定契約（テストコードが定める。ここでは変えない）:
    1・3・5・6・7: REQ-2 統一複合判定（相対誤差 1e-3 未満 または 絶対誤差 1e-5 未満）。6・7 は同デバイスの jacobian 参照も含む。
    2: bit 完全一致（CUDA ネイティブ f64 経路とホスト経路の比較。REQ-2 より厳しい）。bit 不一致による fail は
       テスト自身の bit 一致契約の fail として、パニックメッセージを引用して記録する。ただちに REQ-2 違反とはみなさない。
    4: 型付きエラー（DeviceMismatch）を返すことの検査。parity ではないので exit code と出力件数だけで判定する。
  jvp 系で Unsupported 等の型付きエラーが出た場合も fail として事実を記録する。推測で直さない。
  時間計測ではないので中央値は取らない。テストごとの pass／fail の件数で記録する。

fail 時の扱い:

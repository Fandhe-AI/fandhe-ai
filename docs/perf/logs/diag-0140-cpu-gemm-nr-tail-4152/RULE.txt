1. 目的

  （正方 512 は 117.5。MM-177 `docs/perf/cpu-gemm-m64-jobgrid-diagnosis.md` §3）原因が、NR=12 のタイルの端数
  （n=10 は 12 レーンのうち 2 レーンがゼロ詰め）の無駄かどうかを判定する。対象の MLP は 784→256→10・batch 64。
  変えないもの: tolerance・判定規則・ゲート閾値・依存・本体コード・unreached_0140.tsv（分類の反映は #4168）。
  事前の予想（判定には使わない）: 端数が無駄にする分は kernel 時間の 2/12 が上限で、窓全体では 6〜7% 程度。3〜4 倍の差は端数だけでは説明できない見込み。

3. 計測手順
  ラウンド数は PARAMS の rounds（5）。各ラウンドの前に hw-lock を取得し、load1 < 3.0 を 30 秒間隔で最大 30 分待つ。
  不通過は gate.txt に TIMEOUT と記録し、そのラウンドを正式系列から外す（status=partial・表題は「参考」・確度は書かない）。
  1 round の順序は run_round.sh のとおり: gate → t1 → native。奇数 round は n を昇順、偶数 round は降順で計る。
  計測中にビルド・集計・転送を並走させない（ビルドは round の前に済ませる）。run の差し替え・追加・除外・上書きは禁止。再実行は別ラベルとし旧系列を残す。
  example は cpu_gemm_nr_tail_4152（crates/backend-cpu/examples）。ソースの sha256 を PARAMS の example_sha256 に固定する。

4. 形状と系列
  判定対象（t1 系列のみ）: l2_fwd（Nn・m=64・k=256）と l2_dw（Tn・m=256・k=64）の n=10・12・24。NR=12 なので n_hi=12、n_hi+NR=24。
  record_only: n=8・11・13、l1_fwd（Nn・m=64・k=784）の n=256・264・276（256 mod 12 = 4。#4151 と重なるため判定しない）、
  ref_square_512（GFLOPS の参照点。g の分母に使う）、native 系列（既定プール。n で job grid の列帯数が変わり交絡するので判定に使わない）。
  t1 は RAYON_NUM_THREADS=1・MeasurementConfig::default()・bench_harness::run の median_secs（cpu_jobgrid_bench と同じ計時）。
  isa は Neon、nr は 12 でなければならない（不一致は集計が停止する）。

5. 導出式（round ごと・ファミリごと。t(n) は t1 の median_secs）
  P = t(24) − t(12)                          （NR 1 列パネル分の限界費用）
  t_ideal(10) = t(12) − P·(12 − 10)/12       （端数がなかった場合に n=10 にかかるはずの時間）
  waste = t(10) − t_ideal(10)、w = waste / t(10)
  r10_12 = t(10) / t(12)                     （参考。1.0 以上なら仕事が少ないのに時間が同じか長い）
  t_peak(10) = 2·m·10·k / (同 round の ref_square_512 の t1 GFLOPS × 1e9)
  g = waste / (t(10) − t_peak(10))           （分母が 0 以下なら未定義）
  分類（5 round の値で。この順に判定）:
    1. いずれかの round で P ≤ 0 → 判定不能（限界費用 P が 0 以下の round あり）
    2. 全 round で g が定義され min g ≥ g_main → 主因
    3. min w ≥ w_small → 寄与あり（min w ≥ w_large なら寄与あり（大））
    4. max w < w_small → 無視できる
    5. それ以外（帯が w_small をまたぐ） → 判定不能（揺れの中）
  健全性: n=10 の t1 GFLOPS 中央値が MM-177 §3 の値（PARAMS）の sanity_lo〜sanity_hi 倍の外なら、環境差の可能性を注記し確度を「低」にする（判定は止めない）。
  kernel 腕（1 タイル単体の計時）は実施しない（#3614 で区間の分解能不足と判定済み）。

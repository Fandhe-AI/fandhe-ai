5. 判定 (評価順 FAIL > undetermined (前提ゲート不成立) > REJECT > ADOPT > undetermined。緩めない)
  - Mac mini 側条件: 到達 10 セルがすべて「5 round 中央値 <= 1.00 かつ 5/5 round <= 1.00」、どのセルにも全 5 round で ON/OFF > 1.00 の一貫した後退がなく、checksum と P-BIT が一致。
    いずれかのセルに全 5 round の後退があれば REJECT。
  - GB10 側は §9 の GB10-MODE で選ばれた 1 方式だけを拘束力ありとして採る。3 方式 (perf doc §5.16 の文面案と同じ語) の定義:
      GB10-RECORD := GB10 は P-R0・P-BIT・checksum 一致のみ検査し、性能セルは記録のみで ADOPT に入れない
      GB10-NBSEP := GB10 の各判定セルに NB-SEP を要求し、後退と言えるセルが 1 つでもあれば REJECT
      GB10-GATE-ONLY-STRUCTURAL := GB10 は構造ゲート (P-R0・P-BIT・checksum・P-RT・P-CELLS・P-LOCK・P-GATE) を fail-closed とし、性能は全記録。NB-SEP 条件の後退があれば undetermined (自動 ADOPT しない)
    後退の定義 (NB-SEP 形): 判定セルで 5 round すべてに ON/OFF > 1.00 かつ ON 腕の round 別 median_s の最小 > OFF 腕の最大。
    aggregate.py は 3 方式すべての判定を併記し、拘束力があるのは選ばれた 1 方式だけと明示する。
  - 総合 ADOPT = Mac mini 側条件を満たし、かつ GB10 が選ばれた方式で pass (REJECT・undetermined でない)。
  - GB10-GATE-ONLY-STRUCTURAL で undetermined になったときの扱いは §9 の UNDETERMINED-HANDLING (auto-reremeasure = 3 腕+A/A の再測を自動で足す／return-to-owner = 所有者へ戻す) に従う。
  - 上のどれでもない場合は undetermined。

6. 1 位化の記録 (判定 5 とは独立。ADOPT の可否には使わない)
  - 同じ round の PyTorch (bench_py.py。torch 2.14.0・numpy 2.5.4 の venv) の比 = torch median_s / fandhe median_s を OFF・ON の両腕について出す。fresh と reuse の両方。
    対象は M-CPU-G512/G1024/G2048 (gemm 512/1024/2048)。比 > 1.00 が fandhe の優位。
  - §9 の NOISE-BAND が adopted なら NB-RANGE5 (ON 腕の round 別比の最小〜最大) と NB-SEP (ON 腕の 5 round すべてで比 > 1.0 かつ ON 腕の最小 > OFF 腕の最大) を記録し、
    NB-SEP を満たさないものは「改善傾向・確定せず」と書く。not-adopted なら生の 5 round の比だけを記録する。
  - GB10 は torch の venv がなければ「未計測」。6 フレームワークのスコアボードでの 1 位化は Phase 6 で確定する (本 run は PyTorch だけの比較)。

7. checksum の範囲

10b. TMA（R-TMA-BASE・R-TMA-SEM・R-TMA-XFER。イシュー #2122 PR-B）
  global は 64x96 の f32（要素値は r*1000+c）。tensor map の encoder 引数（box・swizzle・OOB fill・
  座標・expect_tx）はプローブごとに引数化し、期待値は持たず観測値を記録する。
  待ちの方針（上限到達時に転送先の smem を読まない）: mbarrier の待ち（mbarrier.try_wait）は
  まず上限回数（1,000,000 回）まで数える。上限に達して未完了なら、転送先の smem は読まず、到達の
  事実を global（out[0] のマーカー）へ残して __threadfence_system() で出したうえで、上限なしの待ちに
  移る。完了しなければカーネルは終了せず、外部 timeout（orchestrate.sh）がプロセスごと打ち切り、
  aggregate.py は TIMEOUT（判定不能。13a）として扱う（ホストはカーネルの完了を待てないため、記録上の
  正は外部 timeout の proc 記録で、マーカーはホストから読めない）。したがって「完了を確認する前に
  転送先を読む」経路と「転送中に CTA が終了する」経路はなく、CTA 終了後の smem への書き込み
  （未定義動作）は起こらない。cp.async.bulk.wait_group 0（tma.store）と barrier.cluster
  （tma.multicast・clu.dsmem）も上限を持たず外部 timeout に頼る（TIMEOUT）。ダンプ・読み戻しは待ちが
  完了した後にだけ行う。smem は転送前に番兵（0xFEEDFACE）で埋めてダンプする。
  出力ヘッダは全 TMA カーネル共通で [polls] の 1 語（tensor 系 load・multicast はスロットごと）。
  registry テストがカーネルの格納と checker の解釈の一致を検査する。
  tx-count の規約: mbarrier.arrive.expect_tx の総量は、同じ phase で実際に届く転送量（OOB を含む
  box 全体・bulk の長さ・multicast では宛先 CTA ごとの受信量）と一致させ、待つ phase には必ず転送が来る。
  tx-count を実際の転送量より少なく期待する構成は、アンダーフロー（未定義動作）になりうるため計測しない。
  registry テストが、宣言した box／bulk のバイト数と expect_tx の一致・init の count 1・arrive の
  1 か所・待ちの 1 回（parity 0）をソース構造として静的に検査する（実行時の転送量までは保証しない）。
  撤去の経緯: 旧 tma.oob_tx_partial（expect_tx を範囲内の 128 B だけにして残りを第 2 phase で追加）は、
  同じ転送の残量を第 2 phase では補えず、第 1 待ちが完了しない／第 2 phase に転送が来ず永久に待ち続け、
  観測が得られなかった（PR #2475 の Codex P1・Bugbot High）。部分 expect_tx は未定義動作を突くため
  安全な観測方法がなく、プローブごと撤去した。
  順序: smem 初期化の後に全スレッドが fence.proxy.async.shared::cta、mbarrier を init したスレッドが
  fence.mbarrier_init.release.cluster を出してから（multicast は barrier.cluster 同期のあとで）発行する。
    R-TMA-BASE   tma.base_cta（shared::cta）・tma.base_cluster（shared::cluster・cluster 1 起動）:
                 box 転送が完走し、要素座標（内側次元が先）の仮説どおりにビット一致するか（成立の判定）。
    R-TMA-SEM    観測値を候補モデルと突き合わせて記録する（S5 の detail の k=v トークン。判定語は
                 「受理のみ（実行意味論は未検証）」で、観測内容は R-TMA 観測表に出す）:
                 tma.coord（class=ELEM_INNER_FIRST／TRANSPOSED／NONE）・tma.oob_none／oob_nan／
                 oob_neg（inrange・oob_fill=ZERO／NAN／SENTINEL／OTHER・oob_distinct）・
                 〈OOB 要素が complete_tx のバイト数に含まれるか、の問いは oob_none／oob_nan で答える。どちらも
                 expect_tx を OOB を含む box 全体のバイト数（512 B）にしており、完了すれば「OOB も数える」と
                 判定し、完了しなければ上限なしの待ちのまま外部 timeout で打ち切られ TIMEOUT〈判定不能〉
                 になる（事前登録）。tx-count を少なく期待する形では測らない〉・
                 tma.swz32／swz64／swz128（class=LINEAR／XOR_ADDR_BITS／SRC_B64_MODEL〈src の
                 tma_swizzled_chunk_a。64B のみ〉の一致集合。どれとも一致しなければ class=NONE とダンプ全文）。
                 注: 本 box（タイル先頭 1024 B 整列・行 64 B）では SRC_B64_MODEL と XOR_ADDR_BITS は全語で
                 同一になり区別できない（区別にはタイル先頭をずらす必要があるが、swizzle 使用時の smem 整列
                 要件のため作れない）。両者は常に同時に現れ、本プローブは両者の優劣を判定しない。
                 SEM の観測は S5 の detail のキー集合をプローブごとに固定する（coord・swz*: polls・class〈NONE のとき
                 dump が加わる〉／oob_*: polls・inrange・oob_elems・oob_fill・oob_distinct）。過不足は完全性違反。class=NONE・inrange=MISMATCH・
                 oob_fill に SENTINEL を含むものは、判定語（受理のみ）に埋もれないよう R-TMA 観測表の注意欄に
                 明示する（待ちの失敗は観測値ではなく TIMEOUT として現れる）。
    R-TMA-XFER   tma.store（global の読み戻しが既知パターンと一致）・tma.bulk_cta／bulk_cluster
                 （cp.async.bulk の 256 B コピー）・tma.prefetch（完走の目印のみ。効果は観測できない）・
                 tma.multicast（cluster 2・両 CTA の smem が一致）。成立するかを判定する。成立の detail
                 （S6）のキー集合もヘッダ長に従い固定する（base: polls・box_words・bit_exact／
                 bulk: polls・words・bit_exact／store: global_words・bit_exact／prefetch: completion_magic／
                 multicast: cta0_・cta1_ それぞれ polls・mismatched_words）。過不足は完全性違反。
  依存（事前登録。自身が 成立／受理のみ になるときに限り、依存先が同 target で 成立 でなければ
  判定不能にする。評価順）:
    - raw 起動（cuLaunchKernelEx）で動く tma.*・clu.rt2／rt4・ctl.rawmap は対照 ctl.raw に依存
      （判定不能 RAW_LAUNCH_CTL_FAILED）。tensor map 引数を使う tma.*（bulk_* を除く）は ctl.rawmap にも
      依存（RAW_TENSORMAP_CTL_FAILED）。
    - tma.base_cta が 成立 でない target では、tma.* の他のプローブ（base_cluster を除く）を
      判定不能（TMA_BASE_NOT_ESTABLISHED）にする。
    - tma.multicast は加えて runtime cluster 起動の clu.rt2 が 成立 でない target で
      判定不能（CLU_RT2_NOT_ESTABLISHED）。
  自身が拒否・ロード失敗・実行時エラー・結果不一致の場合は、その判定をそのまま採る（依存は
  「動いた」結果の意味を保証する条件）。
  clu.rt2／clu.rt4 は起動時に cluster 次元を与える（cuLaunchKernelEx の CLUSTER_DIMENSION 属性）補助で、
  clu.dims* と同じ出力を観測する。ctl.raw／ctl.rawmap は raw 起動経路の対照で、ctl.rawmap は
  tensor map 引数の ABI（128 B 整列の値渡し・後続引数）を観測する（cuTensorMapEncodeTiled が必要。
  開発機の sm_86 では encode が CUDA_ERROR_NOT_SUPPORTED になる）。

11. setmaxnreg・Hopper との差分（R-SNR・R-HOPPER）
  snr.dec・snr.incdec は既存の setmaxnreg_probe_* 4 ファイルと同じ命令列を再実行する
  （R-LEGACY の突き合わせ対象）。R-HOPPER の表は、全カーネルプローブの Hopper（sm_90a）列
  （compile.log の target=hopper の S2）と sm_121 側の判定を並べ、本来の対応アーキが
  sm_90／sm_90a のものと、sm_121 でだけ受理されるものの両方向を表にする。Hopper 列は
  「GB10 上の NVRTC（ptxas）による受理の実測」であり、Hopper 実機での実行は未検証。
  home が sm_90a のプローブでは hopper 列と home 列の状態が一致しなければならない
  （食い違いは 判定不能 HOPPER_HOME_DISAGREE）。PTX ISA 9.0 の節番号は、確認できていない
  ものを「要確認」と表示する。

12. 既存プローブとの整合（R-LEGACY）
  legacy-*.log（setmaxnreg_probe_* 4 ファイルの再実行。SETMAXNREG_PROBE_RESULT 行）を
  分類し、対応する snr.* の同 target の分類と食い違えば 6 (8) のとおり判定不能とする。
  legacy の分類: run_ok（execute success）／mismatch（execute corrupted。終了コード 101）／
  load_failed／runtime_error／nvrtc_rejected／inconclusive（nvrtc_compile inconclusive）／
  timeout（終了コード 124・終端の結論なし）／process_failed（124 以外の非 0 で終端の結論なし。
  device 初期化の panic〈101〉を含む）。inconclusive・timeout・process_failed は新プローブ側を
  判定不能（LEGACY_INCONCLUSIVE）にする。exit 0 の終端の結論はちょうど 1 つ（0 件・複数は
  完全性違反）。結論が残っているのに異常終了（101 の corrupted 以外）も完全性違反。
  対応: dec_base→(snr.dec, compute_121)・dec_accel→(snr.dec, compute_121a)・
  incdec_base→(snr.incdec, compute_121)・incdec_accel→(snr.incdec, compute_121a)。
  official では legacy ログ 7 件（setmaxnreg 4 件・TMA 3 件）が必須。
  TMA の既存プローブ（tests/tma_probe_real_device.rs）の 3 テストも 1 テストずつ別プロセスで再実行する
  （legacy 名は <テストバイナリ>@<テスト関数>）: tma_execution_probe（cluster 変種）→
  (tma.base_cluster)・tma_execution_probe_cta → (tma.base_cta)。対象 target は legacy ログの
  `tma_compile_probe ... (selected for execution probe)` 行の arch（先頭で受理された arch）。分類:
  run_ok（`tma_execution_probe ... result=success`）／mismatch（exit 101 で転送結果の不一致メッセージ）／
  nvrtc_rejected（全 arch のコンパイル失敗の panic）／process_failed（その他の異常終了。選択 arch なしを含む）／
  timeout。比較の対象 target は legacy が選択した arch のみ（先頭で受理された arch だけ。他の arch の
  結果は比較しない）。選択 arch が正式 target（TARGET 行）の外なら比較を省く（R-LEGACY 表に注記する）。
  選択 arch が無い（target 不明）の legacy は、対応する新プローブの全 target に適用する。
  比較は成否のみ（既存の TMA プローブはロード失敗・実行時エラー等を区別できない panic になるため）:
  legacy が mismatch／nvrtc_rejected（run_ok でない確定した失敗）なのに新プローブが run_ok（またはその逆）なら
  LEGACY_CONTRADICTION。legacy が timeout・process_failed（一過性の失敗を含む）なら RULE 13a と同じく
  LEGACY_INCONCLUSIVE。tma_nvrtc_compile_probe は 6 行の記録のみで比較しない（分類 recorded）。6 行は（変種 cluster／cta）x（arch compute_121／121a／121f）の直積に過不足なく一致することを要求し、件数だけの検査にしない（欠落・重複・未知はいずれも完全性違反。集合照合の方針は guide_claims の claim_id 集合・setmaxnreg 終端行の arch 照合も同じ）。

13a. プロセス異常の扱い（方針: 測定そのものの打ち切り・異常終了は判定不能として集計を続け、
     記録の欠落・矛盾は改ざん・欠落の疑いとして完全性違反にする）
  | プロセス | exit 124 | 124 以外の非 0 | exit 0 だが出力が欠落 |
  |---|---|---|---|
  | env_info（シェルのみ・プロセスなし） | - | - | 必須キー・値の欠落（end_utc なし＝未完了の実行を含む）は完全性違反 |
  | device_attributes_dump | 欠測（TIMEOUT）として報告し集計は続ける（判定に使わない記録用） | 欠測（PROCESS_FAILED）として同様 | 本文なし（proc 行だけ）は完全性違反。proc 記録の欠落・ファイル欠落も完全性違反 |
  | compile | 出たセルは採用。欠測セルに依存する判定は判定不能（TIMEOUT）。env 行も無ければ G0_NVRTC_MISSING | 同（PROCESS_FAILED） | 完全性違反（全セル・done が必須）。完走しているのに非 0 も完全性違反 |
  | exec（(プローブ, target) ごと） | 欠落段の先頭に timeout を合成し判定不能（TIMEOUT）。ctl 段の打ち切りを含む | 同（PROCESS_FAILED）。101 は mismatch を伴う完了のみ許容 | 完全性違反（全セル・done・env が必須）。完走しているのに非 0（101＋mismatch を除く）も完全性違反 |
  | legacy | 分類 timeout → 新プローブ側を判定不能（LEGACY_INCONCLUSIVE） | 結論なしなら分類 process_failed → 同（LEGACY_INCONCLUSIVE）。結論が残っているのは完全性違反 | 完全性違反（終端の結論がちょうど 1 つ） |
  どのプロセス種別でも、proc 記録（SM121_PROBE_PROC 行）の欠落・重複・識別子の不一致は
  完全性違反。official では legacy 7 件・dump・compile・exec 全件のファイルが必須。

13. 入力の完全性（R-COMMON・fail-closed）
  aggregate.py は LogIntegrityError を送出し、正式な集計を一切出力せず非ゼロ終了する:
    - 重複したレコード（値が同一でも拒否。登録口 register_once に一本化）
    - 未知のプローブ・target・stage・status・kind・phase・フィールド、フィールドの過不足
    - 壊れた JSON、NaN・Infinity・浮動小数点・真偽以外の数値型・64 bit を超える整数
    - キー集合の過不足（期待する (プローブ, target, stage) の完全集合。欠落・余剰・未知）
    - 連鎖の矛盾（前段が失敗なのに後段が ok 等）・policy で固定された状態との不一致
    - 完了記録（done）の欠落・件数の不一致、プロセス記録（proc）の欠落・不整合
      （compile・exec・legacy・device_attributes_dump のすべて。打ち切り・異常終了の扱いは
      13a の表。dump の値は記録のみ）
    - セルの arch が期待と異なる（exec: ctl は target・S2 は実アーキ・他は仮想アーキ、
      FIXEDARCH 行のプローブは固定アーキ。compile: home は PROBE 行の home=・hopper は sm_90a）
    - official で legacy ログが 7 件そろわない（dev では 0 件を要求）
    - k=v 形式の記録（attr の detail・legacy 行）内の重複キー
    - env_info.txt の値の不正（git_clean が 0／1 でない・時刻の書式）
    - 未マスクの絶対パス（/home/<name>。検査するのはこの形のみで、ホスト名の残存は検出しない）
    - 開発機 target と正式 target の混在
  detail は切り詰めない。例外・警告を握り潰さない。
  ログがまったく無い場合だけ「未実測」として exit 0、一部だけ欠けていれば exit 非 0。
  終了コード: 0＝正常（G0 成立、または全ログ無し）／2＝完全性違反／3＝G0 不成立
  （表は stdout に出すが --out では書かない）。出力は検証してから一時ファイル経由で
  atomic に書く（公開値は compute 結果の 1 か所から描画する）。

14. 起動プロセス（orchestrate.sh。実測前に固定。PROCESS 行が正）
  | プロセス | 起動回数・順序 | timeout | 出力 | 判定に使う |
  |---|---|---|---|---|
  | env_info | 1・最初（シェルのみ） | - | env_info.txt | G0（provenance） |
  | device_attributes_dump | 1・2 番目 | PROCESS 行の timeout= | device_attributes_dump.log | 記録のみ |
  | compile | 1・3 番目 | PROCESS 行の timeout= | compile.log | S1／S2／home／hopper |
  | exec_matrix | PROBE 行 × 正式 TARGET 行 を 1 プロセスずつ | PROCESS 行の timeout= | exec/<probe>@<target>.log | 全セル |
  | legacy | 7（setmaxnreg_probe_* 4・tma_probe_real_device の 3 テスト各 1）・最後 | PROCESS 行の timeout= | legacy-<name>.log | R-LEGACY |
  provenance（env_info.txt の git_head・git_clean）は、git 作業ツリーなら git から、GB10 ノードの
  ように .git の無い転送先では転送元が書いた .rev-stamp（1 行目: HEAD の 40 桁 16 進・
  2 行目: dirty=<件数>。dirty=0 のときだけ git_clean=1）から読む。どちらも得られなければ
  orchestrate.sh は開始前に停止する（git_source に由来を記録する）。正式実行（--dev-smoke で
  ない実行）で git_clean が 1 でない（git status が空でない。submodule ポインタの変更を含む。
  .rev-stamp に dirty=0 の行が無い 1 行形式を含む）ときは、プロセスを 1 つも起動せず
  exit 1 で停止する。
  timeout 秒数は PROCESS 行の timeout=<秒> が正で、orchestrate.sh はそこから読む
  （--dry-run の出力は timeout= を含み、aggregate.py の self-test が突き合わせる）。
  各プロセスに外部 timeout を付け、終了コードを proc 記録（SM121_PROBE_PROC 行）として
  ログへ追記する。終了コード 124＝timeout。exit 0 は完了記録（done）が必須、101（テストの
  panic）は mismatch または legacy の corrupted を伴う場合のみ許容、124・その他は未完了
  （セルの欠落）が必須で、完了しているのに非 0 は矛盾として拒否する。
  開発機スモーク（--dev-smoke）は DEVTARGET 行の target で exec_matrix の全プローブを回し
  （legacy は回さない）、出力先を呼び出し側が指定したリポジトリ外の scratch ディレクトリに
  限る（realpath -m で .. と symlink を解決してから判定する。コミットしない）。
  既存ログがある出力先では開始前に停止する（上書き・追加起動をしない）。再計測は空の別
  ディレクトリを LOG_DIR に指定する。

  facade の公開面・既存の tests/tma_probe_real_device.rs と tests/setmaxnreg_*。

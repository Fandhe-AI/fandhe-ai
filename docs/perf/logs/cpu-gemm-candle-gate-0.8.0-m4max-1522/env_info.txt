`docs/perf/cpu-gemm-candle-gate-remeasurement.md` §24.11 の Mac 実行手順を実施

## 共通

- 対象イシュー: #1522（CPU GEMM candle 比ゲートの Apple M4 Max 正式値を共有
  環境で確定する。§24.10 の undetermined 解消）
- 目的: `docs/perf/cpu-gemm-candle-gate-remeasurement.md` §24.10 で
  `verdict=undetermined` のまま残っている M4 Max 側の CPU GEMM candle 比ゲート
  （旧 #1117／#1283）正式値を、専有ゲート opt-out（`GEMM_GATE_LOAD_GATE_MODE=
  record_only`）を使って共有負荷下でも一発計測として確定させる
- 転送元コミット（base）: 未実測（Mac セッションが実行した時点の
  `git rev-parse --short HEAD` を記入する）
- 系列: 正式系列のみ（`fandhe-ai =0.8.0` registry 解決）。ラベル
  `0.8.0-1522`（計画 §4 規則 3〈ワンショット規則〉。性能以外の失敗での再試行は
  `0.8.0-1522-r2` 等の別ラベルを使う）
- プロトコル: `GEMM_GATE_LOAD_GATE_MODE=record_only sh
  orchestrate_m4max.sh` → `compare_gemm_gate.py --device cpu`（5 回独立
  プロセス起動・中央値。`run_gemm_gate_cpu.sh` 内部プロトコル自体は不変）
- 判定規則: `docs/perf/cpu-gemm-candle-gate-remeasurement.md` §24.11（事前宣言・
  計測後に変更しない。本イシュー計画 §4 と同一）
- gate mode: `record_only`（専有ゲート opt-out。ルート #1519 のユーザー指示
  「Metal・M4 Max 側は現在の環境で測れる値で大丈夫」を受けた措置。ルート #1519・
  兄弟イシュー #1520 と同型）
- tolerance 契約: #1241 承認・#1443/#1445 実装済み（候補 A-1・`c=0.5`）を適用。
  tolerance 定数・判定式は本イシューで変更していない

1. 同期 1 回の定義: 主指標はホストを止める明示同期 = cuStreamSynchronize + cuCtxSynchronize +
   cuEventSynchronize の呼び出し回数。暗黙に同期しうる呼び出し（非 async の cuMemcpyDtoH*／cuMemcpyHtoD*、
   cuMemAlloc*／cuMemFree*）は別列に record-only で記録する。cuStreamWaitEvent はホストを止めないので
   別列にする。

2. 1 step あたりの回数: 窓 w について n_w = (count(w, K=120) − count(w, K=20)) / 100。
   forward = n_fwd、backward = n_fwd_bwd − n_fwd、update ＋ tape_drop = n_full − n_fwd_bwd、
   infer = n_infer_reuse。同じ式で cuLaunchKernel、HtoD・DtoH の memcpy 回数、確保・解放の回数も出す。
   5 反復で値が一致すれば「決定的」とし、一致しなければ中央値と min–max を記録して「非決定」と書く。
   整数にならない値は丸めずそのまま記録する。コード読解の約 9 回は実測ではない。
   縮退: 窓 fwd／fwd_bwd が状態機械に拒否される場合は、窓を外し「full − fwd を backward ＋ update の
   合算」として記録する（CPU スモークでは全窓が通過したため縮退は不要）。

3. phase 内訳（腕 A）: run ごとの median_s を取り、5 run の中央値と min–max を出す。比は 5 run 中央値
   どうしで取る。負荷ゲートは load1 < 1.0 かつ GPU utilization 0%（30 秒間隔・最大 30 分）。5/5 通過した
   ときだけ正式とし、それ以外は参考扱い（結論にも参考と明記）。run の差し替え・追加起動はしない。

4. infer 内訳（B-2）: fidelity = nosync の合計 / prod の合計（backend 下位層は h2d_upload＋l1_issue＋
   l2_issue＋download の合計と、上位層 chain 区間との比で評価）。0.8〜1.2 を外れたら区間を参考扱いにする。
   kernel_wait は download − download_again の導出値（公開 API から stream を直接同期できないため）で、
   実カーネルを伴う同期の代表値としてだけ使う。上位の固定費 = decomposed の（tape ＋ snapshot ＋ steps）
   ＋ paired/residual。checksum は 5 run で一致することを hard（fail-closed）とする。

5. 固定費（B-3）: sync_idle（空のストリームでの同期）、tiny_roundtrip（1×1×1 GEMM の launch ＋ 同期。
   引数なしの空カーネルの代替であることを明記。空カーネルの起動には新規 unsafe が要るため行わない）、
   L2 の launch_issue（N=128）、L2S の kernel_wait（N=128）。いずれも 5 run の中央値。実カーネルを伴う
   同期の代表値は B-0 の syncsplit kernel_wait と B-2 の kernel_wait とし、空の同期の値だけで見込みを
   立てない（#3180 で空 dispatch 14.5 µs と実カーネル 208〜259 µs が乖離した教訓）。

6. 見込みの式（record-only）:
   - 「同期を相手と同じ 1 回にした場合」の削減見込みは (n_full − 1) × c。c は {sync_idle,
     tiny_roundtrip, 実カーネル同期} の 3 値で幅として出す。
   - 「launch 固定費の上限（CUDA Graph 等で launch 発行を 1 回にまとめた場合）」は
     (launch_count − 1) × launch_issue。
   - 「1 同期あたり約 27 µs」の外挿は (train reuse step_total − infer reuse iter_total) /
     (n_full − n_infer) で再計算し、実測固定費と比べる。
   - いずれも step_total や相手との差に対する説明率（%）と未説明残差を必ず併記する。原因の断定はしない。

7. 判定は aggregate.py の機械出力をそのまま採用し、事後に緩和しない。欠損・非数値・n≠80・checksum

## 2. 候補
- T = 4096 のみ。Stage 0 の結果で T を選び直さない（Stage 0 は T の選定根拠にしない）。

## 3. Stage 0（現状確定。記録 + 前提ゲート）
- コマンド: cargo test -p fandhe-ai-backend-cpu --release --lib mse::tests::mse_backward_threshold_sweep -- --ignored --nocapture
- Mac mini と GB10 で各 5 プロセス。RAYON_NUM_THREADS は unset。
- 記録: n = 640・2560・4096 の seq／par 中央値と r(n) = seq/par の 5 プロセス中央値。
- 前提ゲート:
  (a) 全行で seq と par の checksum が一致すること。不一致は FAIL で停止。
  (b) 両機体とも n in {640, 2560} で 5/5 プロセス r(n) < 1.00。不成立なら undetermined とし Stage 1 へ進まない。

## 4. Stage 1（framework-compare A/B。CPU）
- before = main HEAD の crates/facade。after = 同一コミットで mse.rs の定数宣言 1 行だけを
  `= 4096;` にした計測専用 worktree（コミットしない）。各腕は [patch.crates-io.fandhe-ai] path patch。
- 判定セル: bench-fandhe --task train --size 64 --device cpu --mode {fresh, reuse} の両方。
- --phases 系列は記録のみ（判定に使わない）。
- 5 round 固定。各起動は独立プロセス。round ごとに before/after の起動順を反転。
- checksum は compare の前に JSONL から完全一致を独立確認。不一致は FAIL で停止。
- 比較: compare_gemm_ab.py --task train --threshold 1.00 --per-run --require-checksum-exact
- ハーネス: scripts/bench/framework-compare/run_ab_mse_backward_threshold_cpu.sh

## 5. 負荷ゲート
- Mac mini: AB_ROUND_COOLDOWN_MAX_LOAD1=3.0 のクールダウン + round 開始時 load1 < 3.0。
- GB10: round 開始時 load1 < 1.0。
- 各 round 最大 30 分待ち、gate=pass|timeout|unavailable gate_ok=0|1 を記録。
- 5/5 round が gate_ok=1 の系列のみ正式系列。それ以外は record_only で判定は undetermined。
- 系列開始前に他セッションの cargo・rustc・bench プロセスが 0 件であることを preflight-procs.txt に記録。

## 6. 総合判定
- ADOPT: Stage 0 前提ゲート成立 かつ 両機体の全判定セル（train fresh・reuse）で 5 round 中央値 ratio <= 1.00、
  checksum 完全一致、両機体とも正式系列。
- REJECT: いずれかの機体のいずれかの判定セルが 5/5 round 一貫して後退（全 round で ratio > 1.00）。
- undetermined: 上記以外（ゲート不成立・一部 round のみの後退・Stage 0 (b) 不成立・未計測）。
- FAIL: checksum 不一致、または 3 者 bit 一致テストの失敗。ADOPT にも REJECT にも数えず停止。

イシュー #1238: 候補判定の fandhe-ai 側 parity 非後退契約（ParityBaseline）
への影響を確認する
実行環境記録

## 位置づけ

本ディレクトリの `baseline-impact.md` は実機ベンチではなく、リポジトリに
コミット済みの `crates/backend-cuda/tests/common/parity_baseline.rs`
（`BASELINES` 配列。45 行）に対する机上計算（決定的な純粋関数の適用）の
出力である。GPU 実機は使用していない（本エージェント実行環境は CUDA/Metal
実機なし）。`--scale-mode exact` は各行の入力（Xorshift64Star の Rust 実装
と同一の Python 移植で再現した `A`・`B`）を実際に生成して `max|A|`・
`max|B|` を求める（合計で約 1.2 億要素の生成。重複する `(seed, m, k, n,
dtype)` の組はプロセス内メモ化）。

## 実行コマンド

```bash
cd scripts/bench/framework-compare
python3 parity_baseline_impact.py --scale-mode exact \
  > ../../../docs/perf/logs/candle-parity-tolerance-baseline-impact-1238/baseline-impact.md
```

## 再現性の確認

- 出力（`baseline-impact.md`）は入力ソース（`parity_baseline.rs`）と
  `parity_baseline_impact.py`/`parity_tolerance_candidates.py` の内容のみ
  で決定される純粋関数の適用結果であり、実機依存の非決定性は含まない。
  同一コマンドを 2 回実行し、出力が bit 完全一致することを確認済み（`diff`
  で差分なし）
- `Xorshift64Star` の Python 移植は固定値照合で検証済み
  （`parity_baseline_impact_test.py::XorshiftPortTest`。出典コマンドは
  同テストクラスの docstring 参照）
- `parse_baselines` の実ファイルスモークテスト
  （`RealFileSmokeTest::test_real_file_parses_and_totals_45_rows`）で
  45 行・`ParityPath` 別内訳が期待どおりであることを確認済み

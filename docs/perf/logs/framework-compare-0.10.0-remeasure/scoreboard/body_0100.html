他フレームワークとの勝敗スコアボード

crates.io 公開版 fandhe-ai =0.10.0（2026-10-03 公開）を、同一ハーネス・同一 xorshift64* シード入力で candle-core =0.11.0・burn =0.21.0・PyTorch 2.14.0・TensorFlow（M4 Max 2.16.2＋Metal プラグイン／GB10 2.21.0 CPU）・SciPy 1.18.1 と比較。Hugging Face transformers と LangChain は計算層ではないため性能比較の対象外とし、下の役割対応表で扱う。0.10.0 では Python 3 フレームワーク（PyTorch／TensorFlow／SciPy）も両機体で再計測し、fandhe-ai・candle・burn と同じラウンドの中で同席計測した（0.9.0 版の転記・別セッション流用は解消）。Apple M4 Max（Metal／CPU）は 2026-10-03 に 5 ラウンド計測（{m4_series}。{m4_load}）、DGX Spark GB10（CUDA／CPU）は 2026-10-03（UTC）に 5 ラウンド計測（{gb_load}）し、いずれもセルごとの 5 ラウンド中央値を採った。「勝敗」の区分（1 位／僅差／負け）と「最速他 FW ÷ fandhe-ai」の比は、事前登録規則どおり同一ラウンド内の比（そのラウンドの有効な他フレームワーク最速 ÷ fandhe-ai）の 5 ラウンド中央値で決める（>1 で 1 位、0.90 以上で僅差）。負けの「N 位」と「vs」の相手名は 5 ラウンド中央値で数える。値は中央値 ms（GEMM は GFLOP/s 併記）、推論はバッチ/秒。「0.9.0 比」は同一セル・同一モードの fandhe-ai 中央値の比（<1 が高速化。推論は >1 が改善）。0.9.0 に同モードの記録がないセルは fresh 同士の比とし「（fresh 同士）」と表示する。

何が変わったか（0.9.0→0.10.0。v0.10.0 に含まれる変更）

既定経路の性能変更はなし（性能候補はすべて opt-in）

v0.10.0 は 0.9.0 公開以降の 274 コミットで、中心は機能網羅（#2058 ツリー。facade から使えるようになったものは optimizer・LR scheduler の拡充、Transformer エンコーダ／Pool 等の層、AMP、ONNX import／export の op 拡大と external data 対応、nn::Module／ModuleList／ModuleDict、compat::save_model／load_model など。param groups・EMA・CTC 損失・npy／npz・generate()・バッチ推論 API などは内部クレートに実装されたが facade には未公開。詳細は下の対応表）と Windows ビルド対応（#2481 ツリー）。性能改善候補は CPU（tape arena 再利用 #2448・縮約の逐次フォールバック閾値 #2446）・CUDA（推論チェーンの CUDA Graph #2460・pinned staging 再利用 #2463・elementwise 融合 #2232）・Metal（train forward の encode-only 化 #2457・readback 分割並列コピー #2456・GEMM 候補 #2455・tape_build キャッシュ #2458）がいずれも 既定 OFF の opt-in として入っただけで、本表が測る registry 既定経路の GEMM・学習・推論の選択ロジックは変わっていない（TMA Stage 1 は #2041 で不採用）。したがって上の「0.9.0 比」は主に計測日・負荷の違いによる揺れで、M4 Max の絶対 ms は共有負荷の交絡を含む参考値（判定は同一ラウンド内で同席計測した対戦相手との比が主）。

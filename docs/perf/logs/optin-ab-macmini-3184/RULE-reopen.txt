1. 補遺 RULE 3 の運用改定 (「継承スクリプトと orchestrate.sh は編集しない」の例外を次の 3 点に限る)
  (i)   round 前クールダウン hook (scripts/bench/framework-compare/ab_round_cooldown.sh) の追加。継承 5 スクリプトに
        source 1 行・init 1 行・round ループ先頭の呼び出し 1 行・コメントを足す (既存行の変更・削除なし)。
        環境変数 AB_ROUND_COOLDOWN_MAX_LOAD1 が未設定なら即 return しファイルも作らない (未設定時の挙動は不変)。
        設定時は load1 < 閾値まで 30 秒間隔・最大 1800 秒待ち、round ごとに
        `round<N> cooldown=<pass|timeout|unavailable> threshold=<x> load1=<x> waited_s=<n> at=<UTC>` を記録する。
        閾値は 0 より大きく 8.0 以下の数値のみ受理 (継承閾値より緩い値を受け付けない)。継承の閾値 8.0・gate_ok・series 判定は変えない。
  (ii)  metal-gemm-candidate-ab-2111/aggregate.py の run ログ検証 (check_run_log) と解析 (parse_run) が、
        `--nocapture` で融合する最初の出力行 `^test <AB_TEST> \.\.\. N=<n> arm=<arm> ...` をちょうど 1 回に限り受理する。
        FAILED／panicked の検査・`test result: ok. 1 passed; 0 failed` の検査・独立した `ok` 行の要求・他の全検査は変えない。
        融合 2 回以上・別テスト名・行頭以外・N= 以外の融合は従来どおり拒否する (self-test に固定)。
        旧系列 (steel/) は遡って有効にしない (record_only のまま)。
  (iii) metal-tape-build-infer-phase-2114/orchestrate.sh の host_kind に macmini を追加 (m4max と同じ record_only の経路。
        差分は usage・case 行・コメントのみ)。集計器 (2114/aggregate.py) の正値検査は変えない。
  いずれも判定を緩めない (待機・記録・受理形の限定・識別子の追加だけ) ことを理由とする。

1. 分解能
  - Rust std の Instant は macOS で clock_gettime(CLOCK_UPTIME_RAW) (使用 toolchain の rust-src
    library/std/src/sys/time/unix.rs の 55〜67 行目)。実機の 1 tick は mach_timebase に由来する約 41.7 ns (推定)。
  - 実測は #[ignore] テスト timer_resolution_probe (TIMER_RES 1 行) を timer-res.log に記録する。数値は実測後に
    結論 doc へ記入し、RULE には推定値を判定材料として書かない。FFI (mach_timebase_info) は呼ばない。

2. 計測方法
  - TIMING_BATCH_K = 1000。次の 4 セルに限り 1 サンプル = 「K 回を 1 つの Instant 窓でまとめて計り K で割った値」
    とする: tape_build_micro.tape_new / reuse_decomposed_off.tape_new / reuse_decomposed_on.tape_new /
    reuse_decomposed_on.provider_select (キャッシュ ON のヒット経路)。他のセルは従来どおり 1 回ずつ計る
    (H1 の両辺を比較可能に保つため)。
  - まとめ計時のバッチは add_counters の後 (カウンタ窓・iter_total 窓・tape_build 窓の外) で実行する。
    run_micro は従来の 1 回計時の後に実行する。warmup でも同じバッチを実行する。n = 80 (EXPECTED_N 不変)。
  - JSON 拡張フィールド: timing_method (batched_mean|single_shot)・batch_k・single_shot_median_s・single_shot_q1_s。
    median_s・q1_s・q3_s・min_s・max_s は対象 4 セルではまとめ計時の 80 サンプルの統計。単発値は参考。
  - 既定でこの方式 (env による opt-in にしない)。

3. 0 が残った場合
  - まとめ計時でも median_s が 0.0 のセルが残る、または集計器が別理由 (checksum 不一致・欠落・n != 80 等) で止まった
    場合: 集計器は変えず、H1〜H3 は「未確定 (集計器停止・原因: aggregate.err の要旨)」と書き推定で埋めない。
    生ログを残し所有者に報告する。同じ RULE のまま K を上げて取り直さない (再計測は新しい補遺と新しい label が必要)。

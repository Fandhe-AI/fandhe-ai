== 実行構成（実測値。事前登録した --max-load-avg=4.0 からの逸脱を明記） ==
実行コマンド: cargo run -p fandhe-ai-backend-metal --release \
  --features internal-diagnostics --example gemm_splitk_ab_bench -- \
  --max-load-avg=8.0

**逸脱の理由**: 本マシンは複数の並列実装セッションが常時稼働しており、
計測期間中の 1 分 load average が概ね 5〜7 で推移していた（下記
uptime_before_runN.txt 参照）。`run_gated.sh`（本ディレクトリ）は
`docs/perf/metal-gemm-splitk-shapes-1308` と同じ `--max-load-avg=4.0` を
既定として文書化しているが、実測時点でこの閾値では `EnvGuardExhausted`
（バックオフ再試行 10 回上限到達）が確実視されたため、共有負荷環境下でも
計測を進める実務判断として `--max-load-avg=8.0` を使用した（機械的な
ゲート自体は無効化していない。閾値のみの調整）。この逸脱により、
事前登録コメントの「専有ゲート不成立時は undetermined を 1 回記録して
終了する」という運用は、より緩い閾値の下で行われたことになる
（`docs/perf/metal-gemm-splitk-ab.md` §5「計測環境に関する留保」参照）。

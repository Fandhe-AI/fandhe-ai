### 集計ワンライナー（Python3 標準ライブラリのみ）

16 列の生ログ Markdown 表から `(構成, 経路, scale, shape)` 単位で `fail`／`total` を合計し、`max_abs_diff`／`max_rel_err`／`max_fail_abs_diff` の最大値を取る。**`SHAPES` 定数の意図的重複（`256x256x256` の 2 定義。`m` 由来のシード導出式により同一入力・同一結果になる。プローブのコメント参照）は、集計前に片方（`K sweep base`）を破棄して 1 セットのみ残す**（既存 §2.1/§2.2 と同じマージ方針。単純に両方を合算すると total が二重計上される）。**s=100 の f16 行では 5 シードの一部が `±Inf`（`ref_nonfinite` 列参照）を記録するため、集計 `max()` は非有限値を明示的に伝播させる**（Python の `float()` は `"inf"`／`"NaN"` をそのまま `inf`／`nan` へ変換するため、`max()` に `nan` を混在させると欠損値として扱われず結果が不定になる罠がある。本集計は `nan` を握りつぶしたうえで `inf` は優先的に伝播させる `agg_max` を使い、有限値のみでの部分集計を誤って最終値にしない）。

```python
# 抜粋（全文は本 PR 差分に含む一時スクリプト相当。再現は生ログから機械的に可能）
import math

def parse_file(path, config):
    rows = []
    route = None
    with open(path) as f:
        for line in f:
            if line.startswith("## TF32"): route = "TF32"; continue
            if line.startswith("## f16"): route = "F16"; continue
            if not line.startswith("| ") or line.startswith("| scale |") or line.startswith("|---"):
                continue
            cols = [c.strip() for c in line.strip("|\n").split("|")]
            if len(cols) != 16: continue
            scale, shape, seed, failtotal = cols[0], cols[1], cols[2], cols[3]
            fail, total = map(int, failtotal.split("/"))
            def pf(x):
                # "n/a"／"NaN" は分子側 fail=0 セル固有の欠損表示であり集計対象外。
                # "inf" は f16 表現上限超過（§7 参照）を表す実測値のためそのまま通す。
                x = x.strip()
                return None if x in ("n/a", "NaN") else float(x)
            rows.append(dict(config=config, route=route, scale=scale, shape=shape,
                fail=fail, total=total, max_abs=pf(cols[4]),
                max_rel=pf(cols[6]), max_fail_abs=pf(cols[11])))
    return rows

def dedupe_256(rows):
    # "256x256x256 (block tile x8)" 定義側を捨て "(K sweep base)" のみ残す（重複除去）
    return [r for r in rows if r["shape"] != "256x256x256 (block tile x8)"]

def agg_max(values):
    # None（"n/a"／"NaN"）を除いた実測値のうち、1 件でも inf があれば inf を返す。
    # 有限値だけで max() を取ると inf セルの存在が消え、§3 の集計契約（3 指標の
    # 最大値を取る）に反して見かけ上小さい値が採用されてしまう（本ドキュメント
    # で実際に発生していた不具合。#995 レビュー指摘で修正）。
    finite = [v for v in values if v is not None]
    if not finite:
        return None
    if any(math.isinf(v) for v in finite):
        return float("inf")
    return max(finite)
```

生ログは `docs/perf/tensor-core-tolerance/gb10-sweep-tf32-{auto,opt,basic}.md` として保存済み。上記スクリプトを `python3 script.py docs/perf/tensor-core-tolerance/gb10-sweep-tf32-*.md` の形で再実行すれば、下記 §5〜§9 の各表を再現できる（形状ごとに `(構成, 経路, scale)` でグルーピングし、`fail`/`total` 合計・3 指標の最大値（`agg_max`）を出力するだけの機械的集計）。

## 4. 実行カーネル種別の実測

3 構成それぞれの可用性ヘッダ（プローブ出力そのまま引用）:

```
# --tf32-kernel auto
kernel availability: staged=yes, staged-swizzle group width=8, opt=yes, basic=yes
routing rule: staged if n%4==0 && k%4==0 (swizzle variant if size condition) -> opt -> basic

# --tf32-kernel opt
tf32 kernel select: opt
kernel availability: staged=no (disabled by CudaGemm::new_tf32_opt_only (diagnostic)), staged-swizzle group width=none, opt=yes, basic=yes

# --tf32-kernel basic
tf32 kernel select: basic
kernel availability: staged=no (disabled by CudaGemm::new_tf32_basic_only (diagnostic)), staged-swizzle group width=none, opt=no (disabled by CudaGemm::new_tf32_basic_only (diagnostic)), basic=yes
```

`auto` 構成での形状別ルーティング（`kernel` 列の実測値。`n%4==0 && k%4==0` を満たす形状は `staged`、それ以外は `opt` に載る。全形状で `basic` への降格は発生しなかった）:

| ルーティング先 | 形状 |
|---|---|
| `staged` | 32x32x32・64x64x64・128x128x128・256x256x256（両定義）・512x512x512・100x100x100・64x96x128・256x256x512・256x256x1024・256x256x4096 |
| `opt` | 1x1x1・17x23x19・17x19x23・33x31x65・130x70x90 |
| `basic` | （auto 構成では未使用。opt 強制構成で全形状 `opt`、basic 強制構成で全形状 `basic` になることは可用性ヘッダで確認済み） |

f16 経路（`CudaWmmaGemm::run_f16`）は `--tf32-kernel` の影響を受けず、`kernel` 列は常に `wmma_f16`。プローブ出力からは `wmma_f16_opt` の可用性・使用可否を分離判定する情報が得られないため（f16 opt/basic 強制入口は未実装）、**f16 側のカーネル版内訳は「不明・分離不能」として扱う**（`docs/spec/` の対象外・将来拡張として §10 に記録）。

## 5. 重要な実測事実: TF32 の staged／opt／basic は数値的に完全一致する

3 構成の生ログを `kernel` 列を除いて突合したところ、**全形状・全スケール・全シードで `staged`／`opt`／`basic` の出力（`fail/total`・`max_abs_diff`・`mean_abs_diff`・`max_rel_err`・`mean_rel_err`・percentile 列・`max_fail_abs_diff`）が完全一致した**（`diff` 差分 0 行。`kernel` 列を同一プレースホルダへ置換したうえでの比較）。すなわち GB10 では TF32 WMMA カーネルのタイル戦略（共有メモリ有無・swizzle 有無）が誤差分布に一切影響しない。これは #994 doc §6「基本版との差分表」を埋める結果でもあり、**差分は全形状で「なし」**である。

この事実により、以下 §6〜§9 の TF32 集計表は `auto` 構成の値を代表として掲載し、`opt`／`basic` は別掲しない（値が同一のため冗長な重複を避ける。生ログ自体は 3 構成分とも保存済みなので、構成別に見たい場合はそちらを参照できる）。

**カーネル版差の混同に関する留保（§4 を再掲）**: TF32 経路は `--tf32-kernel <auto|opt|basic>` の強制入口（#994）により `basic`（sm_86 実測時点のカーネルソースと同一）を明示選択して比較できたが、**f16 経路（`CudaWmmaGemm::run_f16`）には同等の opt/basic 強制入口が存在しない**。`crates/backend-cuda/src/gemm_wmma.rs` の実装上、f16 も `wmma_f16_opt`（最適化版）と基本版の 2 種類が存在し、`run_f16` は opt 版が利用可能なら自動的にそちらを使う（`wmma_f16_opt_available()` が `true` の場合）。したがって以下の比較は「sm_86 実測時点に自動選択されていたカーネル版」と「GB10 `auto` 構成で自動選択されたカーネル版」を突き合わせたものであり、**両者が同一カーネル版だったかどうかは本ドキュメントの実測からは判定できない**（プローブ出力から opt/basic の使用可否を分離判定する情報が得られないため。§4）。TF32 で見られた「GPU 世代差のみを反映する比較」という条件をf16 は満たしておらず、**下表・結論は「カーネル版差と世代差が混在した参考値」として扱う**（§996 の閾値改定検討では GB10 実測値の直接転用を推奨しない）。

## 11. 結論と制約

- 閾値定数（`RELATIVE_TOLERANCE`・`ABSOLUTE_RESCUE_THRESHOLD`）・判定式・テスト許容誤差は本ドキュメントでは変更していない。
- **`max_fail_abs_diff` の `s²` 比例は TF32 経路で全 14 形状（1x1x1 を除く）・全スケール（0.1/10/100）で成立を確認した**（`r(s)` の範囲 0.942〜1.333、事前固定基準 `|log10 r| ≤ 0.3` を全セルで満たす）。§3.2 の絶対誤差救済閾値候補（`[-1, 1)` スケール限定の暫定値）を他スケールへ換算する場合、`s²` 倍が妥当な近似になることを実測で裏付けた。
- **`max_rel_err` はスケール不変に近い**（大半の形状で比 0.58〜1.27）が、要素数の少ない形状（17x19x23 等）では桁落ちキャンセレーションによる外れ値が生じうる。
- **sm_86（Ampere）→ GB10（sm_121・Blackwell 系譜）の世代差は TF32 経路では実質的に見られないことを確認した**（`basic` カーネル同士〈同一ソース〉の比較で fail 率・`max_fail_abs_diff` がほぼ一致。§10 TF32 節）。**f16 経路は世代差の有無を確定できていない**（§10 f16 節。sm_86・GB10 双方で自動選択されたカーネル版〈opt／basic〉を識別・強制する手段がなく、観測された小さな差が世代差かカーネル版差か分離不能なため、下表は参考値に留める）。#186 §5 が既定していた「sm_121 へ数値を外挿しない」という留保は、TF32 側の傾向（fail 率・s² 比例・相対誤差不変性）については GB10 でも成立することが確認できたため、REQ-2 改定検討（#996）において TF32 の sm_86 実測を GB10 の参考値として扱うことは妥当と考えられる（ただし個々の絶対数値そのものの厳密な転用は推奨しない。GPU 間差は表示桁レベルで残る）。f16 側の外挿可否は本ドキュメントでは未確定のまま残る。
- **GB10 では TF32 の `staged`／`opt`／`basic` カーネルが数値的に完全一致する**（§5）。#994 doc §6「基本版との差分表」はこの結果により「全形状で差分なし」として埋まる。
- **制約（本ドキュメントで実施していない事項）**:
  - f16 経路には opt/basic 強制入口が存在せず、f16 の世代差とカーネル版差は分離できない（§4）。
  - f16 は `s=100` で出力が f16 表現上限（65504）を超え広範囲に ±Inf 飽和するため、`s=100` の f16 データは精度評価に使えない（§7）。`s=10` までは飽和なしで評価可能。
  - 累算誤差項（FP32 累算 vs 入力丸め）の定量的な切り分けは実施していない（既存 §3.1 の未実施事項がそのまま残る）。
  - 3 案（閾値改定候補）の推奨・決定は #996 のスコープ外のため行っていない。

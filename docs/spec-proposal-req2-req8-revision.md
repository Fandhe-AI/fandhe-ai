## 1. REQ-2 複合判定の改定提案

### 1.1 未解消状態の整理

REQ-2 の統一複合判定（相対誤差 1e-3 未満 または 絶対誤差 1e-5 未満。`docs/spec/04-requirements.md:74`）は、
CUDA Tensor Core 経路（TF32 WMMA・f16 mma）で恒常的に不合格であることが実測済みである。

- イシュー #186（TASK-11.1g）は「変更が必要」と結論して 2026-08-06 に close 済みだが、閾値定数
  （`backend_cpu::parity::RELATIVE_TOLERANCE`＝1e-3・`ABSOLUTE_RESCUE_THRESHOLD`＝1e-5）は close 後も
  変更されていない（`docs/perf/cuda-tensor-core-tolerance-evaluation.md` §4「結論」）。
- TF32 経路（`CudaGemm::run_wmma_tf32`、基本版）は最小形状（32×32×32）を含む全 15 形状・全シードで
  複合判定の不合格率が約 15〜16.5% に達する（同ドキュメント §2.1 実測表・同「要旨」）。唯一の例外は
  要素数 1 の縮退形状（1×1×1）。
- f16 WMMA 経路（`CudaWmmaGemm::run_f16`）は K≤256 では不合格率 0% だが、K=512 以降で不合格が発生し、
  K=4096（PoC-v2-5 stress ケース）で不合格率 0.174% に達する（同 §2.2 実測表。K に対して単調増加）。
- `docs/perf/cuda-parity-baseline.md`（イシュー #389 系列。実測記録本体は `docs/backend-cuda-real-device-testing.md`
  §5.3）が定める数値一致 parity の恒常 fail 対象、および `docs/perf/cuda-optimized-remeasurement.md`
  「数値一致（parity）状態の限定条件」節が Phase F 後も再確認した内容は、いずれも上記 TF32／f16 経路の
  不合格が現時点でも解消していないことと整合する。
- **（#996 追記）** GB10（sm_121）実機での再実測でも同様の不合格が確認されている: TF32 経路は
  15 形状・全スケール（`s`∈{0.1,1,10,100}）で fail 率が概ね 15〜19% に達し（`max_fail_abs_diff` は
  `s²` 比例。`docs/perf/cuda-tensor-core-tolerance-gb10-scale-sweep.md` §6・§8）、f16 経路も `s`≤10 で
  K=512 以降 fail が発生する（同 §7）。sm_86（Ampere）実測（本節上記）と GB10（sm_121・Blackwell 系譜）
  実測は、TF32 経路に限り誤差分布に有意な世代差が見られないことも確認済みである（同 §10 TF32 節。
  f16 経路はカーネル版差と世代差が分離できず参考値扱い、同 §10 f16 節）。

### 1.2 改定候補 3 案の比較と推奨案（#996 更新）

`docs/perf/cuda-tensor-core-tolerance-evaluation.md` §4「結論（変更要否）」が整理した改定候補 3 案を、
1.3 節の 3 検証（入力スケールスイープ・opt 版再実測・GB10 実機再実測）の実測結果に照らして比較する。
本節が新たに追加する数値判断は 1.5 節の判定式・係数のみであり、3 案自体の列挙は上記ドキュメントを
踏襲する。

| 案 | 実測に照らした評価 | 採否 |
|---|---|---|
| 案 1: 経路別の**固定**絶対誤差救済閾値 | TF32 の `max_fail_abs_diff` は全 14 形状・`s`∈{0.1,10,100} で `s²` 比例が成立する（`r(s)` の範囲 0.942〜1.333、事前固定判定基準 `\|log10 r\| ≤ 0.3` を全 42 セルで満たす。`docs/perf/cuda-tensor-core-tolerance-gb10-scale-sweep.md` §8）。固定値（例: `[-1, 1)` 入力限定の暫定値 2.535e-2 超）は `s`=10 で約 100 倍不足・`s`=0.1 で約 100 倍過大になり、単一スケールにしか妥当しない | **固定値のままでは不採用**。1.5 節の正規化版（案 1′）へ置換 |
| 案 1′: 経路別・**入力スケール正規化**した絶対誤差救済（`docs/perf/cuda-tensor-core-tolerance-evaluation.md` §3.3 が示した代替案の具体化） | `max_fail_abs_diff / (s² · √K)` が TF32 で GB10 全 14 形状・全 4 スケール（**56 セル**。2026-08-29 #1002 レビュー指摘反映・訂正）にわたり 2.75e-4〜5.53e-4 の狭い範囲に収まる（1.5 節 §手順 1 の導出表）。f16 は同比が TF32 より 2〜3 桁小さい範囲に収まる（同節手順 3） | **推奨（主案）** |
| 案 2: f16 の K 依存スケーリング／K 実用上限 | f16 の fail は `s`=1 では K≥512 で発生する（`cuda-tensor-core-tolerance-evaluation.md` §2.2）が、`s`=10 では K=128 でも発生する（`cuda-tensor-core-tolerance-gb10-scale-sweep.md` §7: 128×128×128 の `s`=10 行 6/81920 fail）ため、K 上限のみではスケール依存の効果を吸収できない。さらに `s`=100 では f16 出力が表現上限（65504）を超え広範囲に ±Inf 飽和する（同 §7 `ref_nonfinite` 列）ため、これは閾値ではなく**適用条件**の問題である | 主案（案 1′）の `√K` 因子に K 依存の効果を吸収する。飽和は 1.5 節 §3.3 の「適用条件」へ併記する |
| 案 3: 高精度要求時に Tensor Core 経路を選ばないディスパッチ方針の明示 | 閾値の代替にはならないが、精度トレードオフの利用者向け明示として有用。非 Tensor Core 経路（f32 FMA）は現行の統一複合判定を満たす（`docs/spec/04-requirements.md:74` PoC-v2-5 実測記録） | **併記推奨（補助案）**。REQ-2 本文の改定ではなく、1.6 節の改定文案に REQ-11 側の参考注記として付す（REQ-11 自体の改定は本提案の主対象外） |

は正規化式の `√K` 因子に吸収し、案 3（ディスパッチ方針の明示）は補助的な利用者向け注記として併記する。
判定式・係数の導出は 1.5 節、REQ-2 側の改定文案は 1.6 節に記す。

### 1.3 実施済み検証と記録先（#996 更新）

旧版（#580 作成時点）は下記 4 項目のうち (a)〜(c) を「閾値の具体値を確定する前提条件」として
**未実施のまま**列挙していたが、#992 ツリーの完了により (a)〜(c) はいずれも**実施済み**となった。

- **(a) 入力スケールスイープ: 実施済み**。プローブ対応は #993（`crates/backend-cuda/examples/wmma_tolerance_probe.rs`
  の `--scales`／`WMMA_TOLERANCE_PROBE_SCALES` オプション）で行い、実測は #995 の GB10 実機実行で完了した
  （`docs/perf/cuda-tensor-core-tolerance-gb10-scale-sweep.md` §6〜§9、生ログは同 §12）。TF32 経路の
  `max_fail_abs_diff` が `s`∈{0.1,1,10,100} の全形状で `s²` 比例することを確認済み（同 §8）。
- **(b) opt 版カーネルでの再実測: 実施済み**。`docs/perf/cuda-tensor-core-tolerance-opt-remeasurement.md`
  §5〜§7 が opt 版実測を記録し、`docs/perf/cuda-tensor-core-tolerance-gb10-scale-sweep.md` §5 が
  「GB10 では TF32 の `staged`／`opt`／`basic` の 3 カーネルが数値的に完全一致する」ことを確認したため、
  #580 作成時点で残っていた「§2.1 の TF32 実測は基本版限定」という留保は解消している。
- **(c) GB10（sm_121）実機での再実測: 実施済み**。`docs/perf/cuda-tensor-core-tolerance-gb10-scale-sweep.md`
  §2（計測環境）・§10（sm_86 との世代差比較）。TF32 経路は sm_86（Ampere）→ GB10（sm_121・Blackwell
  系譜）で誤差分布に有意な世代差が見られないことを確認した（同 §10 TF32 節）。
- **(d) 累算誤差項の定量的切り分け: 未実施のまま**（参考事項）。TF32 経路の不合格率が K に依存しない
  観察について、「入力丸め×条件数が支配項である」という帰属は依然として未検証の仮説にとどまる
  （`docs/perf/cuda-tensor-core-tolerance-evaluation.md` §3.1）。1.5 節の判定式導出はこの帰属に依存しない
  （理論的動機として `s²` 比例・`√K` 成長という実測で確認済みの性質のみを用いる）。

**残る制約**（1.5 節の適用条件・限界として詳述）:

- f16 経路には opt/basic 強制入口が実装されておらず、f16 の世代差とカーネル版差は分離できない
  （`docs/perf/cuda-tensor-core-tolerance-gb10-scale-sweep.md` §10 f16 節）。
- f16 は `s`=100 で出力が f16 表現上限（65504）を超え広範囲に ±Inf 飽和するため、`s`=100 の f16 データは
  精度評価に使えない（同 §7）。`s`≤10 までは飽和なしで評価可能。
- 生ログ（`docs/perf/tensor-core-tolerance/gb10-sweep-tf32-*.md`）には出力スケール（`max|C_ref|`）の列が
  存在しないため、出力スケールによる直接正規化は本提案では評価不能である（1.5 節手順 5）。

### 1.5 推奨判定式と係数の導出（#996 新設）

#### 1.5.1 判定式

Tensor Core 経路（CUDA `wmma_tf32` 系・`wmma_f16`／`mma_f16`）限定で、REQ-2 の統一複合判定に次の
経路別・入力スケール正規化した絶対誤差救済項を追加する案を推奨する（非 Tensor Core 経路は現行の
統一複合判定をそのまま維持する）。

```
pass ⇔ rel < 1e-3  または  diff < max(1e-5, τ_path · S_A · S_B · √K)

  S_A = max|A|, S_B = max|B|（入力の要素最大絶対値）
  K   = GEMM の縮約長（内積の項数）
  τ_TF32・τ_f16 は経路別の無次元係数（下記手順で導出）
```

一様分布 `[-s, s)` の入力プローブでは `S_A ≈ S_B ≈ s` であり、`S_A · S_B ≈ s²` となる（`s` の記法は
`docs/perf/cuda-tensor-core-tolerance-gb10-scale-sweep.md` と統一）。

**既存絶対誤差救済との関係（#1002 レビュー指摘反映・2026-08-29 再訂正）**: 上記救済項は既存の絶対誤差
救済（`diff < 1e-5`）を `max(1e-5, ...)` の形で包含し、既存救済を**置き換えるのではなく下限として
維持したうえで正規化項を追加する**。正規化項 `τ_path · S_A · S_B · √K` が `1e-5` を上回るか否かは
経路・`s`・`K` に依存し、1.3 節・1.5.2 節の実測検証範囲 `s`∈{0.1,1,10,100} 全体で一様に上回るわけ
ではない（当初「この範囲では常に 1e-5 を上回る」としていた記述は誤りであり本訂正で修正する）:

- **TF32**（`τ_TF32 = 2e-3`）: 検証した全形状（K=19〜4096）・全スケール `s`∈{0.1,1,10,100} で
  正規化項が `1e-5` を上回る。最小値は `s`=0.1・K=19（17×23×19 形状）の
  `2e-3 × 0.01 × √19 ≈ 8.72e-5 > 1e-5` であり、正規化項が常に支配的になる。
- **f16**（`τ_f16 = 2e-5`）: `s`∈{1,10} では検証した全 K（19〜4096）で正規化項が `1e-5` を
  上回る（最小値は `s`=1・K=19 の `2e-5 × 1 × √19 ≈ 8.72e-5 > 1e-5`）。一方 `s`=0.1 では
  `2e-5 × 0.01 × √K = 2e-7 · √K` となるため `1e-5` を上回るのは `K > 2500` の場合に限られる
  （検証形状では `256×256×4096` のみ該当）。それ以外の検証形状（K≤1024）では `s`=0.1 時に
  正規化項が `1e-5` を下回り、既存の絶対誤差救済 `1e-5` が支配する（例: `s`=0.1・K=19 で
  `2e-7 × √19 ≈ 8.7e-7 < 1e-5`）。

すなわち f16 経路・`s`=0.1・K≤1024 の組合せは検証範囲**内**でも正規化項が `1e-5` を下回る
（検証範囲外の小スケールに限られるわけではない）。いずれにせよ、正規化項が `1e-5` を下回る場合に
従来の絶対誤差救済（`diff < 1e-5`）で合格していた近ゼロ・相殺結果が新契約で不合格になる契約後退を
防ぐため、`max(1e-5, ...)` 定義を採用する（`max` の性質上、新救済項は既存救済より広くなることは
あっても狭くなることはなく、構造的に非後退が保証される）。

**理論的動機**（2〜3 行）: TF32 は入力を仮数部 10bit に丸めてから積和するため、入力丸めの相対誤差
自体はスケール非依存であり（`docs/perf/cuda-tensor-core-tolerance-evaluation.md` §3.1 の unit
roundoff `u ≈ 4.88e-4`）、積の絶対誤差は入力スケールの積 `S_A · S_B` に比例する。K 項の和で生じる
独立な丸め誤差の蓄積は最悪ケースで K に比例するが、符号がランダムな場合は √K で成長するという
標準的な誤差解析に従う。`docs/perf/cuda-tensor-core-tolerance-gb10-scale-sweep.md` §8（`s²` 比例の
実測確認）・§9（`max_rel_err` のスケール不変性）がこの動機を裏付ける。

**適用範囲の限定（#1002 レビュー指摘反映）**: 上記 `√K` 則の係数導出（1.5.2 節）は一様乱数
（`[-s, s)` 一様分布）プローブの実測にのみ基づく。理論的動機の段落で述べたとおり、独立な丸め誤差の
蓄積は「符号がランダムな場合」に限って `√K` 成長にとどまり、最悪ケースでは K に比例しうる。構造化
入力・同符号入力・強い相殺を伴う入力ではこの独立性の仮定が崩れるため、本判定式は**一様乱数プローブで
検証済みの入力分布**への適用を前提とし、構造化・同符号・強相殺入力を含む一般 GEMM 入力への外挿は
本提案の実測では未検証である。spec 側で REQ-2 の一般契約として確定させる前に、決定的な悪条件入力
（同符号入力・強相殺入力等）または実運用分布での K スイープにより上界を確認するか、確認が完了する
までは検証済み入力条件（一様乱数プローブ）への適用範囲の限定を維持することを推奨する（5 節
「スコープ外」に追加検証事項として記録する）。

**S_A・S_B のテンソル全体スケールに関する既知の限界（#1002 レビュー指摘反映）**: `S_A = max|A|`・
`S_B = max|B|` はテンソル全体の要素最大絶対値であり、要素ごと・出力セルごとの局所スケールではない。
そのため A・B の一部に極端な外れ値が 1 つでも存在すると、その外れ値と無関係な出力セルに対しても
救済項 `τ_path · S_A · S_B · √K` が一様に拡大され、本来の局所誤差スケールに見合わない過大な許容誤差
を与えうる。この効果は本提案の実測（一様分布プローブ。全要素が概ね同じ振幅で外れ値を含まない）では
観測されない（一様分布では `S_A・S_B` が全セル共通の代表スケールとして妥当なため）が、外れ値を含む
一般 GEMM 入力への適用可否は本提案の実測範囲外であり未検証のまま残る。要素ごと・タイルごとの局所
正規化への置き換えは将来課題として 5 節に記録する。

**契約の適用範囲（#1002 レビュー指摘反映）**: 上記 2 点の限界（`√K` 則の独立丸め誤差前提・`S_A・S_B`
のテンソル全体スケール前提）により、本判定式は REQ-2 の統一複合判定を**一般 GEMM 入力に対して置き
換えるものではない**。適用範囲を次のとおり明確化する: 一様乱数プローブで検証済みの入力分布に対して
のみ、正規化救済項 `diff < max(1e-5, τ_path · S_A · S_B · √K)` を追加的な救済条件として適用してよい。
構造化・同符号・強相殺入力・外れ値を含む入力に対しては、正規化救済項の妥当性が未検証であるため
**適用せず**、REQ-2 の現行統一複合判定（`rel < 1e-3` または `diff < 1e-5`）をそのまま適用する
（Tensor Core 経路がこれらの入力で不合格になること自体は 1.1 節記載の既知の現状であり、本提案が
新たに生む欠落ではない）。すなわち本提案は「一様乱数プローブで検証された入力についてのみ Tensor Core
経路の parity 判定基準を緩和する」限定提案であり、一般契約の改定を主張するものではない。1.6 節の
改定文案はこの限定を前提とした**未確定候補**として提示する（そのまま spec 側へ確定転記できる文案
ではない。1.6 節冒頭参照）。

#### 1.5.2 係数導出手順

1. **TF32（GB10・`auto` 代表）**: `docs/perf/cuda-tensor-core-tolerance-gb10-scale-sweep.md` §6 の
   全 14 形状（1×1×1 を除く。fail 0% のため `ρ` が定義できない）× 4 スケールについて、
   `ρ = max_fail_abs_diff / (s² · √K)` を算出する。K は各形状の第 3 次元（第 3 の GEMM 寸法）。
   §5 が示すとおり staged／opt／basic は GB10 で数値的に完全一致するため、opt 版・staged 版でも
   同じ `ρ` が成立する。**56 セル**（14 形状 × 4 スケール。1×1×1 除く 14 形状はいずれの
   スケールでも `max_fail_abs_diff` が非ゼロであるため 56 セル全てで `ρ` が定義できる。
   2026-08-29 #1002 レビュー指摘反映: 当初「42 セル」としていたのは §1.2 案 1 行の
   `|log10 r(s)| ≤ 0.3` 判定〈14 形状 × `s`∈{0.1,10,100} の 3 スケール比〉のセル数との混同で
   あり、本節の `ρ` 集計対象とは異なる。数値再計算は下記ワンライナーの入力データを 56 セル分に
   拡張して実施し、範囲・最大値は変わらないことを確認済み）の `ρ` は **2.75e-4〜5.53e-4** の
   範囲に収まり、最大値は
   `512×512×512（`s`=10）`の **5.533e-4**（`math.fsum` 等を使わない単純な浮動小数点演算での再計算値。
   下記ワンライナー参照）。
2. **TF32（sm_86・`s`=1、参考照合）**: `docs/perf/cuda-tensor-core-tolerance-evaluation.md` §2.1 の
   `s`=1 相当データ（`[-1, 1)` 入力）で同じ `ρ` を算出すると、範囲は 2.75e-4〜4.41e-4（最大値は
   `512×512×512` の 4.413e-4）で GB10 側の範囲に収まる（世代差なしの §10 確認と整合）。
3. **`τ_TF32` の確定**: `compare` の判定式は `diff < ABSOLUTE_RESCUE_THRESHOLD`（狭義不等号）であり、
   「表示値は丸め済みのため丸め前の実値を厳密に超える必要がある」という既存の注意（同評価ドキュメント
   §2 冒頭注記）を踏襲し、`ρ_max`（5.533e-4）の 2 倍以上の余裕を確保した切りの良い値として
   **`τ_TF32 = 2e-3`** を提案する（余裕倍率 `2e-3 / 5.533e-4 ≈ 3.61` 倍）。
4. **f16（GB10・`ref_nonfinite = 0` の行のみ）**: `docs/perf/cuda-tensor-core-tolerance-gb10-scale-sweep.md`
   §7 のうち非有限値を含まない行（`s`≤10 の全形状。`s`=100 は飽和のため除外）で同じ `ρ` を算出すると、
   最大値は `256×256×4096（`s`=10）`の **4.883e-6**。
5. **f16（sm_86・`s`=1、K=4096、参考照合）**: `docs/perf/cuda-tensor-core-tolerance-evaluation.md` §2.2 の
   K=4096 行（`max_fail_abs_diff = 4.883e-4`）で同じ `ρ` を算出すると **7.630e-6** となり、GB10 側の
   最大値より大きい。**f16 は世代差とカーネル版差が分離できていない**（1.3 節・
   `cuda-tensor-core-tolerance-gb10-scale-sweep.md` §10 f16 節）ため、保守的に両者の最大値
   （7.630e-6）を infimum の代表値として採用する。
6. **`τ_f16` の確定**: `ρ_max`（f16。7.630e-6）の 2 倍以上の余裕を確保した切りの良い値として
   **`τ_f16 = 2e-5`** を提案する（余裕倍率 `2e-5 / 7.630e-6 ≈ 2.62` 倍）。
7. **出力スケール直接正規化の評価可否**: `docs/perf/tensor-core-tolerance/gb10-sweep-tf32-auto.md` 等の
   生ログ列（`scale | shape | seed | fail/total | max_abs_diff | mean_abs_diff | max_rel_err | mean_rel_err
   | p50/p99/p999_abs_diff | max_fail_abs_diff | abs margin | rel margin | kernel | ref_nonfinite`）を
   確認したところ、出力側の実測スケール（`max|C_ref|` 等）に相当する列は**存在しない**。したがって
   出力スケールによる直接正規化は本提案では評価不能であり、入力スケール（`S_A・S_B`）由来の
   正規化を採用する。プローブへの出力スケール列追加は将来課題として 5 節（スコープ外）に記録する。

再計算に用いた Python3（標準ライブラリのみ）ワンライナーの骨子（`docs/perf/...` の表の値を手で転記して
算出。生ログの機械可読な再現手順自体は `cuda-tensor-core-tolerance-gb10-scale-sweep.md` §3「集計
ワンライナー」を参照）:

```python
import math
rho = lambda max_fail_abs_diff, s, K: max_fail_abs_diff / (s**2 * math.sqrt(K))
# 例: 512x512x512, s=10, K=512, max_fail_abs_diff=1.252e0（gb10-scale-sweep.md §6）
rho(1.252e0, 10, 512)  # => 5.533e-4
```

起票する運用を提案として記載する」としている。本提案はこれを引き継ぎ、spec リポジトリへの起票は
**親イシュー 1 件に本提案（REQ-2／REQ-8 改定）と G-1（新 REQ 追加提案）の 2 本の提案文書を添付する形**
での一本化を提案する。両提案のスコープ境界（既存 REQ の改定 vs 新 REQ の追加）に重複がないことを
起票時に明記する。

G-1 §8 の F-7 行（「`dependsOn` #577 のため未完」）は、#577 が CLOSED 済みかつ本提案文書が作成された
時点で解消しているため、`docs/spec-proposal-fp8-int8-quant-gemm.md` §8 の当該行を本文書への参照へ

### 3.2 G-5（#591）との一本化

## 4. 結論・ユーザーへの提案事項

- 本文書は spec リポジトリへの改定提案の**草案**である。spec 側での起票判断（イシュー #580 の受け入れ
  基準が求める起票判断）は人間（ユーザー）に委ねる。
- 承認が得られるまで、本リポジトリでは閾値定数（`RELATIVE_TOLERANCE`・`ABSOLUTE_RESCUE_THRESHOLD`）・
  REQ-8 下限値（`crates/bench-harness/src/threshold.rs::floor_spec`）に関わるコード変更を行わない。
- **（#996 更新・2026-08-29 #1002 レビュー指摘反映）** REQ-2 改定の最終閾値について、1.3 節の 3 検証
  （入力スケールスイープ・opt 版再実測・GB10 実機再実測）はすべて実施済みとなった。1.5 節はその実測
  結果に基づく判定式 `diff < max(1e-5, τ_path · S_A · S_B · √K)` と係数（`τ_TF32 = 2e-3`・
  `τ_f16 = 2e-5`、いずれも実測 `ρ_max` の 2 倍以上の余裕を確保。`ρ` の集計対象は TF32 で 56 セル
  〈14 形状 × 4 スケール〉）を**推奨案**として提示するが、**1.6 節の改定文案は未確定候補にとどまる**
  （そのまま spec 側へ確定転記できる文案ではない）。理由は 2 点: (1) 正規化項の `√K` 則は一様乱数
  プローブで検証済みの入力分布にのみ根拠があり、構造化・同符号・強相殺入力への外挿は未検証、
  (2) `S_A = max|A|`・`S_B = max|B|` はテンソル全体スケールのため、外れ値を含む入力では無関係な
  出力セルの許容誤差まで拡大しうる（いずれも 1.5.1 節）。このため本判定式は一様乱数プローブで検証
  済みの入力分布への適用に限定し、検証範囲外の入力には現行の統一複合判定をそのまま適用することを
  1.6 節の改定文案に明記した。`max(1e-5, ...)` により既存の絶対誤差救済からの後退がないことは構造的
  に保証される（1.5.1 節）が、この非後退保証と上記 2 点の未検証性は独立の論点であり、後者の解消
  （決定的悪条件入力・外れ値を含む入力での上界確認）が spec 側での一般契約化の前提条件である。
  最終採否は spec 側・ユーザー承認事項であり、本文書はこの推奨案を確定値として断定しない。累算誤差項
  の定量的切り分け（1.3 節 (d)）・f16 の opt/basic 強制入口・出力スケール直接正規化の評価・
  構造化/同符号/強相殺入力・外れ値への `√K` 則／`S_A・S_B` 正規化の外挿検証は未実施のまま残る
  （1.5 節・5 節）。
- REQ-8 表更新は 2.1 節の対照表のとおり、本リポジトリで既にユーザー承認済みの確定値（`performance-floor-decision.md`
  §8・§9・§10）をそのまま spec 側へ反映する提案であり、新たな数値判断は含まない。ただし 2.2 節の
  CUDA 行限定条件は表更新後も継続記載することを提案する。
- 3 節の一本化調整（G-1 との親イシュー共有・G-5 の REQ-12 改定不要判断の反映）を、spec 側起票時の
  運用として提案する。

## 5. スコープ外（#996 新設）

イシュー #996 の実装過程で現スコープ外と判断した事項を記録する（本提案・本リポジトリでは対応しない）。

- **f16 経路の opt/basic 強制入口の追加**: TF32 と同様の `--tf32-kernel` 相当の強制入口
  （`internal-diagnostics` feature 限定のコンストラクタ）を `CudaWmmaGemm` へ追加し、f16 の世代差と
  カーネル版差を分離する再実測（`docs/perf/cuda-tensor-core-tolerance-gb10-scale-sweep.md` §10 f16 節・
  §11「是正手段」）。
- **プローブへの出力スケール（`max|C_ref|`）列の追加**: 1.5 節手順 7 が示すとおり、現行の生ログには
  出力スケールに相当する列が存在せず、出力スケール直接正規化の評価には拡張が必要。
- **`compare` API の正規化判定対応・閾値定数の変更**: `crates/backend-cpu/src/parity.rs::compare` へ
  `S_A`・`S_B`・`K` を渡す経路の追加、および `RELATIVE_TOLERANCE`・`ABSOLUTE_RESCUE_THRESHOLD` の変更は
  spec 側での REQ-2 改定確定後に別 Issue で対応する。
- **累算誤差項（FP32 累算 vs 入力丸め）の定量的な切り分け**: 1.3 節 (d)。未実施のまま残る参考事項。
- **REQ-8 表（2 節）の再確認**: REQ-2 改定が spec 側で解決した後、2.2 節が継続記載する CUDA 行限定条件
  （候補算出経路が REQ-2 parity 恒常 fail 対象と一致する点）の再確認が必要。
- **`√K` 則の構造化・同符号・強相殺入力への外挿検証（#1002 レビュー指摘反映）**: 1.5.2 節の係数導出は
  一様乱数プローブの実測のみに基づく。決定的な悪条件入力（同符号入力・強相殺入力等）・実運用分布での
  K スイープにより上界を確認する追加検証は未実施のまま残り、spec 側で REQ-2 の一般契約として確定
  させる前提条件として本提案は位置づける（1.5.1 節「適用範囲の限定」参照）。
- **`S_A・S_B` の外れ値を含む入力への適用可否検証（2026-08-29 #1002 レビュー指摘反映・新設）**:
  `S_A = max|A|`・`S_B = max|B|` はテンソル全体スケールであり、一部要素の外れ値が無関係な出力セルの
  許容誤差まで拡大しうる（1.5.1 節「S_A・S_B のテンソル全体スケールに関する既知の限界」参照）。外れ値
  を含む入力での実測検証・要素ごと／タイルごとの局所正規化への置き換え可否の検討は未実施のまま残り、
  上記 `√K` 則の外挿検証と合わせて spec 側での一般契約化の前提条件とする。

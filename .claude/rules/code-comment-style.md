# コメント規約

## 目的

後続の読み手（Claude を含む）は渡された情報からしか判断できない。
コメントはクレート・モジュール視点での役割と、他クレート・他バックエンドとの
文脈を埋め込み、ファイル単体で文脈が伝わる状態にする。

## 何を書くか

- このクレート・モジュール・関数の役割と責務境界（1〜2 行要約をドキュメンテーションコメントで）
- 呼び出し元・呼び出し先の文脈（「〜から呼ばれる」「〜を呼んで〜を返す」）
- 他クレート・バックエンド間の契約（cfg 依存・数値一致の複合判定・FMA 契約・同期方式の前提）
- 非自明な前提・副作用・エラー処理の意図（例: `cudarc` 動的ロードで toolkit 非搭載でもビルド成立する理由、`prost-build` を使わない理由）
- spec 由来の根拠（REQ 番号・PoC-v2 番号・`docs/spec/` の該当箇所）

## 何を書かないか

- コードを読めば分かる逐語説明（`i += 1;  // i をインクリメント` 等）
- 陳腐化しやすい実装詳細の重複（コードと 2 重に管理しない）

## ドキュメンテーションコメントの形式

- Rust: クレートルートに `//!`、公開 API に `///` を付ける。公開 API の入口には必ず 1〜2 行の役割要約を付ける
- YAML・Makefile・シェル: ファイル冒頭に役割・参照元（どの規約・どのリポと同一方針か）をコメントで記す
- 言語は日本語（japanese-style.md 準拠）
